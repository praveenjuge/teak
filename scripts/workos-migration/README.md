# WorkOS migration operations

Production moved to WorkOS on 2026-10-07. The user import, preflight, witness bootstrap, development social-owner binding and R2 readiness tools finished their jobs and were removed; recover them from git history if they are ever needed again.

What remains are the cutover and rollback controls, kept until Better Auth is retired. Use Bun with `--no-env-file`, supply the exact deployment name, and never paste a WorkOS key into a command, journal, report or repository. Every real rollback step still requires separate explicit approval.

Prepared Phase 5 operator controls:

- `quiesce-importer.ts --deployment <exact> --environment-id <exact> --client-id <exact> --receipt <private-path> --operation establish` is read-only unless `--apply --approval-reference <separate-approval>` is supplied. Establish requires account changes paused and signups frozen; active or uncertain importer intent cannot be displaced. The invocation receipt survives a lost response; use its `.held` receipt for `verify` and separately approved `release`. Preserve the held barrier across cutover/rollback failures.
- `rollback-lifecycle.ts --deployment <exact> --receipt <held-receipt> --report <new-private-path>` is a read-only dry run. Its report lists the exact permanent owners it would invalidate, mark verified or fence, with a count and SHA-256 per class, plus every owner-to-provider link and the denied owners. `--apply` also needs `--password-policy invalidate-all-mapped-legacy-passwords`, separate `--policy-approval-reference` and `--activation-approval-reference`, and `--reviewed-dry-run <that report>` from the same held barrier.
  - `migration/workosRollback:applyPage` requires that reviewed scope. In the same transaction as its writes, and before any of them, it refuses the whole page if any owner is selected outside its reviewed class, links to a different provider user, or is newly denied. The CLI sends only the reviewed entries for the owners at each cursor, so every call stays page-sized; an owner without entries counts as unmapped, unselected and undenied, which fails closed. Provider events that land while account changes are paused therefore cannot add, swap or relink an owner into the write; a refused page changes nothing.
  - The CLI also refuses before dispatching any page when the fresh plan already strays from the review, and checks links and denied owners again after the last page.
  - A lost acknowledgment reruns with a fresh report path and the same reviewed dry run. Pause and barrier stay held on every stop.
- `quiesce-importer.ts`, `rollback-lifecycle.ts` and `revoke-legacy.ts` run their Convex child through `runConvexFunction`: Bun dotenv off, every ambient deployment selector blank, and no WorkOS key, so only `--deployment` picks the target.
- After a separately approved WorkOS-primary flip, `revoke-legacy.ts --deployment <exact> --receipt <confirmed-held-receipt>` verifies the barrier read-only. `--apply --approval-reference <separate-revocation-approval>` drains Better Auth sessions, OAuth access/refresh pairs, and native pending codes in bounded batches, proving completion with empty pages. A cursor scan removes exact installed-version OAuth code/consent and social-state payloads, preserving password-reset, email-verification, and refresh-replay records. Ambiguous candidates remain untouched and block completion with a private row-ID-only review artifact. Transactional verification/native creation gates prevent late grant writes while the barrier is held. It retains account writes paused and the barrier held; it never flips authentication or unpauses. Completion evidence is private and append-only.
- Full transition automation is incomplete: final reconciliation and phase-boundary backup evidence, legacy auth ingress drain, lifecycle rollback application, and the calendar/runtime gates must still be satisfied. This command is step 5 preparation, not cutover authorization. Rollback password policy still requires its separate decision and writer.

Rollback password policy is pending a separate decision: conservatively invalidate every mapped legacy password because the current provider payload does not expose a complete credential revision. The prepared proposal is in the encrypted migration-backup directory. The read-only rollback plan also exposes unavailable canonical profiles, email conflicts, verification downgrades and new owners without legacy accounts; each blocks a safe flip until resolved. Do not invalidate credentials or execute rollback without its explicit activation approval.
