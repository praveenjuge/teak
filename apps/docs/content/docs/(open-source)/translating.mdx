The web app (`apps/web`), the browser extension (`apps/extension`), the card view MCP clients show (`packages/mcp-app`) and the Apple and Android apps (`apps/apple`, `apps/android`) are translated into Spanish, Portuguese (Brazil), German, French, Japanese, Korean and Simplified Chinese. Every word people read comes from the catalogs in `packages/i18n` (`@teak/i18n`). Raycast, these docs and emails are in English. To choose a language in the app, see [Language](/docs/features#language).

![Settings → Appearance with the language menu open, listing Teak's eight languages](../images/language.webp)

## Where things live

| What | Where |
|---|---|
| Locales, cookie name, `intlLocale` | `packages/i18n/src/locales.ts` |
| The English catalog (the source) | `packages/i18n/messages/en.json` |
| One catalog per language | `packages/i18n/messages/<locale>.json` |
| Hooks: `useTranslations`, `useUiLocale`, `useIntlLocale` | `@teak/i18n/react` |
| A translator outside React | `createTeakTranslator` from `@teak/i18n` |
| Term glossary | [Glossary](#glossary) on this page |
| Server error messages | `errors.*` keys, `apps/web/src/lib/serverErrors.ts`, `hooks/useServerErrors.ts` |
| The native apps' catalogs (the `native`, `apple` and `android` namespaces) | `packages/i18n/messages/native/<locale>.json` |
| Generated native files | Apple: `TeakCore/Resources/Localizable.xcstrings`, `Teak/Resources/InfoPlist.xcstrings`, the Safari extension's `_locales`. Android: `core/i18n/src/main/res/values*/strings.xml`, `locales_config.xml` |

The signed-in web app gets its locale from the `teak-locale` cookie (read in `AuthenticatedAppProvider`), which mirrors the account's Language setting. Without a provider, for example in tests or a screen outside the app shell, components render English.

## Adding or changing text

1. Add the English text to `en.json` under the component's namespace, for example `cardModal.menu.replaceImage`. Namespaces follow the component or area (`settings.footer`, `sidebar`, `cardModal.menu`). Reuse a `common.*` key only when the word means the same everywhere (Cancel, Close, Undo).
2. Read it with `const t = useTranslations("cardModal.menu")` and `t("replaceImage")`.
3. Add the same key to all seven other catalogs in the same pull request, translated with the [glossary](#glossary). `scripts/repo/i18n-catalog.test.ts` fails when a catalog lacks a key or its placeholders differ from English.
4. Run `bun test scripts/repo/i18n-catalog.test.ts`, then look at the screen in the language (Settings → Language), and in the pseudo-locale (`?__locale=en-XA`, development only).

## Native apps

The Apple and Android apps read the same catalogs, converted to each platform's own format. The native text lives in its own files, `packages/i18n/messages/native/<locale>.json`, so the web never downloads it.

- **Namespaces.** `native.*` is text both apps show, under the same key on each, so a phrase reads the same on iPhone and Android. `apple.*` and `android.*` hold platform-only text, such as Mac menu commands (Title Case, as macOS menus expect), the Safari popup, permission prompts and the upload notification. The apps can also read the web's `common`, `errors`, `cards.types`, `search.colorHues`, `search.suggestions`, `search.visualStyles` and `settings.language` keys, which mean the same everywhere (`SHARED_WEB_NAMESPACES` in `packages/i18n/src/native.ts`).
- **Messages.** Placeholders and at most one plural per message. No `select`, tags or number formats: Apple's string catalogs and Android's resources can't express them. For text that varies by a value, such as the done verbs, use one key per value (`native.done.markAs.read`, `native.done.markAs.watched`…). `scripts/repo/i18n-catalog.test.ts` enforces this.
- **Reading text.** Swift: `tr("native.library.title")`, `tr("native.common.cardCount", count: n)`. Kotlin: `tr("native.library.title")` in a composable, or `UiText.of("native.library.title")` in a ViewModel or `core:model`, resolved where it's shown. A message's plural count goes in `count`; its other values are strings, in the order the English message first uses them.
- **After changing a catalog,** regenerate both apps' files:

  ```bash
  bun --no-env-file run apps/apple/scripts/i18n.ts --write && bun --no-env-file run apps/android/scripts/i18n.ts --write
  ```

  `apps/apple/tests/i18n.test.ts` and `apps/android/tests/i18n.test.ts` fail when the generated files drift, and when a `tr` or `UiText.of` call names a missing key or passes the wrong values.
- **Language.** The apps follow the account's language, like the web. Settings → Language changes it, and so does the system's per-app language list (iOS, macOS, Android 13 and later), which the app saves to the account on its next launch. Signed out, they follow the device. Dates and numbers format in the app's language: `AppLanguage.locale` on Apple, the configuration's locale on Android.

## Writing messages

- **Whole sentences, never concatenated.** Put values in placeholders: `"Moved {count, plural, one {# card} other {# cards}} to {folder}"`.
- **Plurals** use ICU: `{count, plural, one {# card} other {# cards}}`. Japanese, Korean and Chinese only use `other`.
- **Markup inside a sentence** uses tags and `t.rich`: `"Read the <link>docs</link>"` with `t.rich("key", { link: (chunks) => <a href="…">{chunks}</a> })`.
- **Attributes and toasts** count too: `aria-label`, `title`, `placeholder`, `alt`, and the text of `toast(...)`, `toast.success(...)` and `toast.error(...)`.
- **Data arrays** (menu items, options, shortcut lists) keep a stable `id` and a message key, not an English `label`. Build the visible label with `t` where it renders.
- **Helpers outside React** (in `lib/`) that return text take a translator argument, typed `TeakTranslator<"namespace">`, instead of returning English.
- **Server errors:** show `useServerErrors().message(error, fallback)`. It translates every known server message and card code and falls back to the server's English text.

## What stays English

- "Teak", plan names where the glossary says so, and search syntax: qualifiers (`is:fav`, `type:image`, `tag:`) and date words, which people type.
- Text the server stores on cards: link facts, bylines, price labels, import errors.
- Developer surfaces: the public API, MCP tool descriptions and CLI output.
- Phrases people type to confirm, such as "delete account".

## Dates and numbers

Format with `Intl`, passing `useIntlLocale()` as the locale (or `intlLocale(locale, …)` outside React). In English it returns the locale the code used before translation: `useIntlLocale()` gives `undefined` (the browser's locale) and `useIntlLocale("en-US")` gives `"en-US"`, so English output doesn't change. Never write a fixed `"en-US"`; lint flags it.

## Lint

- Biome `noJsxLiterals` flags text between JSX tags in `apps/web/src` and the extension's `entrypoints` and `components`.
- `scripts/lint/no-ui-string.grit` flags words in `aria-label`, `title`, `placeholder`, `alt` and toast calls, plus fixed `"en-US"` locales.
- Tests and `apps/web/src/components/ui/**` (shadcn primitives) are exempt. Punctuation and "Teak" are allowed.

## Glossary

Use these terms in every catalog, so a word means the same thing on every screen.

Never translate:

- **Teak**, the product name.
- **Pro**, the paid plan's name.
- Search syntax people type: qualifiers (`is:fav`, `type:image`, `tag:`, `folder:`), `OR`, and date words (`today`, `last week`).
- Key names in shortcuts (⌘, Shift, Esc, Enter).

Translate meaning, not words: short UI labels stay short. Keep ICU placeholders, tag names and plural categories exactly. Use sentence case where the language has case, and the language's own punctuation.

| Language | Register |
|---|---|
| Spanish (es) | formal, `usted` |
| Portuguese, Brazil (pt-BR) | `você` |
| German (de) | formal, `Sie` |
| French (fr) | formal, `vous`; a narrow no-break space (U+202F) before `:` `?` `!` `;` |
| Japanese (ja) | polite, です/ます; plain nouns for buttons and menu items |
| Korean (ko) | 합니다 style for sentences; plain nouns for buttons and menu items |
| Chinese, Simplified (zh-Hans) | neutral; full-width punctuation |
