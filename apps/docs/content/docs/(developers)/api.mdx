## Base URL

Production: `https://teakvault.com/api/v1`

The machine-readable OpenAPI document is available at `https://teakvault.com/api/openapi.json`. Local development URLs are in the [Development guide](/docs/development).

## Authentication

Every API request uses a bearer token in the `Authorization` header.

:::warning[Keep secrets out of logs]
Never commit `teakapi_` keys or paste them into public issue trackers. Rotate a key immediately if it leaks.
:::

Generate a long-lived `teakapi_` key in Teak Settings. Each account can have
up to 10 active keys, and new keys can be created at most five times per
minute. Use **Revoke all keys** if you need to clear every key, including any
that no longer appear in the list.

```bash
Authorization: Bearer teakapi_...
```

Native clients using browser sign-in send short-lived OAuth access tokens instead — see [Development](/docs/development#public-api-and-mcp).

Browser-based OAuth clients can discover the active server from `/.well-known/oauth-protected-resource/mcp`, then read its `/.well-known/oauth-authorization-server` document. Teak publishes first-party client IDs and the matching issuer at `/.well-known/teak-oauth-clients.json`. The shared SDK's `discoverAuthServer(siteUrl)` caches a validated result for up to 60 seconds; use `{ forceRefresh: true }` after sign-in or refresh failures. Discovery never sends an access token. For a cloud development backend with a local sign-in server, pass its explicit loopback origin as `localIssuer`; remote metadata cannot enable loopback access by itself.

When a deployment uses WorkOS, request `https://teakvault.com/api` as the OAuth resource. REST requests require a Connect user access token with that exact audience, including in local development. AuthKit session tokens and tokens issued for `https://teakvault.com/mcp` are rejected. Teak API keys remain supported.

### Disconnect an OAuth connection

On WorkOS deployments, send `POST /v1/oauth/disconnect` with your Connect API access token as the bearer credential and no body. A `204` confirms that this grant is permanently disconnected; other grants for the same app stay connected. Repeating the request succeeds. Keep saved credentials until you receive `204`.

An expired, correctly signed access token can disconnect its own grant, but cannot access cards. Invalid credentials return `401`; temporary verification or storage failures return `503`. API keys, refresh tokens, AuthKit sessions, and MCP-audience tokens cannot use this endpoint.

## Read your identity

`GET /v1/me` accepts an API key or OAuth access token and returns
`{ "data": { "id": "...", "email": "...", "name": "..." } }`. `id` is your stable
Teak owner ID; `name` is optional. Invalid, expired, revoked, or deleted-account
credentials return 401. Responses are not cached.

## Create your first card

<CodeGroup>
```bash curl
curl https://teakvault.com/api/v1/cards \
  --request POST \
  --header "Authorization: Bearer $TEAK_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: first-card" \
  --data '{
    "content": "# Project notes\n\nKeep the original spacing.",
    "cardType": "text",
    "tags": ["project"]
  }'
```

```js JavaScript
const response = await fetch("https://teakvault.com/api/v1/cards", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.TEAK_API_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": "first-card",
  },
  body: JSON.stringify({
    content: "# Project notes\n\nKeep the original spacing.",
    cardType: "text",
    tags: ["project"],
  }),
});
```
</CodeGroup>

## Create behavior

`cardType` is optional. Set it to `text` to preserve raw Markdown exactly, even when the content looks like a URL, quote, or color. When omitted, Teak automatically detects links, quotes, and palettes.

## Edit a card

Send changed fields to `PATCH /v1/cards/:cardId`: `content`, `notes`, `tags`,
`url`, or `metadataTitle`. Titles work for every card type, are trimmed, and
can contain up to 512 characters. Send `null` or a blank title to clear it.
Omit `metadataTitle` to preserve the existing title. Metadata processing
preserves titles you edit or clear.

## Upload files

File cards use a direct upload flow, so large bytes never pass through the REST API.

<Steps>
  <Step title="Create an upload">
    Send the file name, media type, and size to `POST /v1/uploads`.
  </Step>
  <Step title="Upload the bytes">
    `PUT` the file to the returned presigned URL and retain its `ETag` response header.
  </Step>
  <Step title="Create the card">
    Send the returned `fileKey`, retained `fileEtag`, and file metadata to `POST /v1/cards`.
  </Step>
</Steps>

Files can be up to 100 MB. Uploaded `.md` and `.markdown` files become editable text cards, must contain valid UTF-8, and are limited to 512 KiB. `.mdx` remains a document.

Supported uploads include common image, audio, video, source, design-token, document, archive, and Figma formats. The [API Reference](/reference) is the canonical source for accepted fields and validation responses.

## Endpoint overview

| Route | Purpose |
| --- | --- |
| `/v1/me` | Read your authenticated Teak identity |
| `/v1/cards` | Create or list cards |
| `/v1/uploads` | Start a direct file upload |
| `/v1/cards/bulk` | Create or update multiple cards |
| `/v1/cards/changes` | Read incremental card changes |
| `/v1/tags` | List tags |
| `/v1/cards/:cardId` | Read, update, or delete one card |
| `/v1/cards/:cardId/restore` | Restore one card from Trash with POST |
| `/v1/cards/:cardId/favorite` | Favorite or unfavorite one card |

See `/openapi.json` or the [API Reference](/reference) for methods, parameters, schemas, and response examples.

## Search and favorites

Search and favorites are filtered card listings. `GET /v1/cards` supports
these query parameters:

      type: "string",

/>

- Search: `GET /v1/cards?q=design&include=content,metadata`
- Favorites: `GET /v1/cards?favorited=true&include=content,metadata`
- Multiple card types: `GET /v1/cards?type=image&type=link&include=content,metadata`

The `include=content,metadata` pair returns full-card fields. The list
response is paginated (`items` plus `pageInfo`). Repeat `type` for an OR filter;
a single `type` remains supported. Invalid types return 400. When loading the
next page, keep the same filters and pass `pageInfo.nextCursor` as `cursor`.

`include=metadata` adds palette `colors` (`hex` and optional `name`), resolved
`linkPreviewMedia`, and the link's site name, author, publisher, and publish
date when present. `include=processing` adds `aiTranscript`; the single-card
response includes these display fields without an `include` parameter. Link
preview media contains temporary resolved URLs, never storage keys.

Image card responses include intentionally different URLs: `thumbnailUrl` is the optimized grid rendition, `compactUrl` is a smaller rendition for compact lists, `placeholderUrl` is a tiny loading placeholder, `detailUrl` is the optimized full-card rendition, and `fileUrl` remains the signed original used for downloads. These URLs are temporary, signed credentials — consume them as returned instead of storing or modifying them. See the [API Reference](/reference) for field details.

## Errors

Errors keep a stable `{ code, error }` shape and can also include `requestId`, `details`, or `retryAt`.

```json
{
  "code": "INVALID_INPUT",
  "error": "Body must include `content` or `url`"
}
```

Use the returned request ID when contacting [Support](/docs/support). For MCP tool contracts, continue to the dedicated [MCP guide](/docs/mcp).

## Check for a saved URL

`GET /v1/cards/duplicate?url=<encoded-url>` accepts the same bearer credentials as other card endpoints. It checks the exact URL against your non-deleted cards and returns `{ "cardId": "..." }`, or `{ "cardId": null }` when no match exists. The URL must use HTTP or HTTPS and be at most 8,192 characters. Invalid input returns 400; invalid or revoked credentials return 401.

### Trash and visual filters

List Trash with `GET /v1/cards?trashed=true`. Repeat `style`, `hue`, or `hex`
parameters to match any value within each filter, combining different filters. Each dimension accepts up to 24 values; excess values return `400 INVALID_INPUT`.
Broad searches that exceed the read limit return `400 INVALID_INPUT`; add a type or date filter to narrow them.
Hex colors accept three, four, six, or eight digits with an optional `#` (URL-encode it as `%23`).
For example: `GET /v1/cards?type=image&hue=blue&hex=%23112233`.

`DELETE /v1/cards/:cardId` moves a card to Trash. Restore it with
`POST /v1/cards/:cardId/restore`. Both return 204 with no body.
`DELETE /v1/cards/:cardId?permanent=true` permanently removes the card and its files.
