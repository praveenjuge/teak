# Sunset list

Compatibility code Teak keeps on purpose, and what has to be true before each
piece can go. Add an entry when you keep code only for old clients or old
data, and delete the entry in the PR that removes the code.

| Code | Kept for | Remove when |
| --- | --- | --- |
| `accountChangesPaused` in `auth:getAuthMode` (`packages/convex/auth.ts`), always `false` | Released Apple and Android builds decode it as a required field. The pause switch itself is gone. | Every supported Apple and Android build is one that no longer reads it. |
| Better Auth component mount (`convex.config.ts`), `legacyBetterAuth.ts`, `migration/exportBetterAuth.ts`, and the `@convex-dev/better-auth` and `better-auth` packages | Retained pre-WorkOS data: account deletion cleans a legacy owner's rows, and the backup exporter reads them. | The retention period in `migrations/workos/README.md` ends and the owner approves deleting the data. Unmounting the component deletes it. |
| `accountDeletionStates.initiationProvider: "betterauth"` (`schema.ts`) | Deletion rows started before WorkOS. Only `"workos"` is written now. | A backfill clears or rewrites those rows. |
| `workosApplicationDisconnects.recoveryReceipt` and the `disconnectRecoveryReceipt` validator (`schema.ts`) | Disconnect rows from the previous Connect flow, which still deny their app (`migrations/workos/README.md`). Nothing inserts new rows. | Those rows have completed or been cleared. |
| `exportJobItems` table (`schema.ts`), `dataExport:recordSnapshotPage`, `getExportCardsPage` and `deleteJobItemsPage`, their allowlist entries, the row fallback in `apps/files-worker/src/workflows/export.ts`, the `deleteJobItemsPage` call in the maintenance workflow's export cleanup, and the `exportJobItems` read in `accountDeletionBatch.ts` | Exports now keep their snapshot in workflow step state. Runs that snapshotted into rows before, or while Convex lacked `getExportSnapshotPage`, still read and drain them; rows a failed drain left behind go when a ready export expires, or with the account. | Every export run started before the Convex deploy has ended (a few days after it), and `exportJobItems` is empty in production. |
| `cards.placeholderHash`, `derivativeVersion`, `derivativeCheckedAt` (`schema.ts`) | Stored rows may still hold them. No code reads or writes them. | A backfill unsets them on every card; then drop them from the schema. |
| `pendingUploadCleanupStates` table (`schema.ts`) | Production may still hold the cursor rows of the hourly pending-upload sweep, which R2 event notifications and the Files Worker's weekly sweep replaced. No code reads or writes it. | The table is empty in every deployment (clear it from the dashboard if not); then drop it from the schema. |
| `adminDailySnapshot` in `packages/convex/telemetry/crons.ts` | The Convex cron that ran the admin snapshot before the Files Worker did; a firing already queued at deploy time still finds it. It now only queues the Worker's snapshot. | The backend deploy that removed the cron from `crons.ts` has run a day. |
| `LEGACY_ONBOARDING_CARD_CONTENTS` (`card/defaultCards.ts`) | Admin stats recognise onboarding cards created before they were marked. | Those cards are backfilled with the current marker. |
| Raycast `apiKey` preference (`apps/raycast/src/lib/preferences.ts`) | People who pasted an API key before browser sign-in existed. | Raycast drops API-key sign-in. |
| CLI credentials without a `binding` (`apps/cli/src/runtime.ts`, `legacy-logout.test.ts`) | Credential files saved before the CLI recorded which server issued them. | Those tokens have expired everywhere (refresh tokens included). |
| `emitCardOutcome`, `emitUserCreated` and `emitCardProcessingFailed` in `packages/convex/telemetry/events.ts` | Jobs mutations scheduled before their events moved to the workflow dispatch outbox. Nothing schedules them now. | The deploy that stopped scheduling them has run in production for a day (scheduled jobs run within seconds). |
| Row staging for imports: `dataImport` `insertItems`, `getPendingItems`, `createPendingBatch`, `failItems`, `setExtractedFile`, their `workflowRpcAllowlist.ts` entries, and the Files Worker's `indexPage` / `importBatches` path in `src/workflows/import.ts` | Imports queued before `importJobs.stagedItems`, which keep staging every item as an `importJobItems` row until they finish. | No import job without `stagedItems` is still active (imports go stale after six hours, so a day after the deploy is enough). Keep `importJobItems`, `getUnclaimedFileKeysPage`, `deleteItemsPage` and the account deletion code for its rows: failed items still live there. |
| `exif.takenAt` (`imageExifValidator` in `schema.ts`) and the fallback that reads it in the viewer's zone (`formatTakenAt` in `apps/web/src/lib/exif.ts`, `ExifFacts` in `CardFacts.swift`, `Exif` in `Exif.kt`) | Released Apple and Android builds format `takenAt` in the device's zone, and photos processed before `takenAtClock` have only `takenAt`. | Every supported Apple and Android build reads `takenAtClock`, and a backfill has written `takenAtClock` on every image card that has `takenAt`. |
| `cards.aiTranscript` (`schema.ts`), the fallbacks that read it (`readCardTranscript` in `card/textContents.ts`, `omitCardText` in `card/queryUtils.ts`, the default `transcript` of `buildCardSearchText`, `cardNeedsAiMetadata`, `cardPreviewText`, `buildEmbeddingText`, local search and the admin rows), and `migration/moveCardTranscripts.ts` | Transcripts saved on the card before they moved to `cardTextContents`. New ones are never written there. | `migration/moveCardTranscripts` has run in production with `dryRun: false` and a dry run reports `transcriptsToMove: 0`; then drop the field from the schema in a second deploy. |
| Index `by_aiSummary_aiTags_aiTranscript_isDeleted_createdAt` (`schema.ts`) and `migration/backfillAiPending.ts` | The AI backfill now reads `by_aiPending_and_isDeleted_and_createdAt`; the old index stays only as `backfillAiPending`'s source of cards to flag. | `migration/backfillAiPending` has run in production with `dryRun: false` and the new reader has run for a day; then drop the index and delete the backfill. |
