# Sunset list

Compatibility code Teak keeps on purpose, and what has to be true before each
piece can go. Add an entry when you keep code only for old clients or old
data, and delete the entry in the PR that removes the code.

| Code | Kept for | Remove when |
| --- | --- | --- |
| `accountChangesPaused` in `auth:getAuthMode` (`packages/convex/auth.ts`), always `false` | Released Apple and Android builds decode it as a required field. The pause switch itself is gone. | Every supported Apple and Android build is one that no longer reads it. |
| Better Auth component mount (`convex.config.ts`), `legacyBetterAuth.ts`, `migration/exportBetterAuth.ts`, and the `@convex-dev/better-auth` and `better-auth` packages | Retained pre-WorkOS data: account deletion cleans a legacy owner's rows, and the backup exporter reads them. | The retention period in `migrations/workos/README.md` ends and the owner approves deleting the data. Unmounting the component deletes it. |
| `accountDeletionStates.initiationProvider: "betterauth"` (`schema.ts`) | Deletion rows started before WorkOS. Only `"workos"` is written now. | A backfill clears or rewrites those rows. |
| `workosApplicationDisconnects.recoveryReceipt` and the `disconnectRecoveryReceipt` validator (`schema.ts`, `schema/validators/workos.ts`) | Disconnect rows from the previous Connect flow, which still deny their app (`migrations/workos/README.md`). Nothing inserts new rows. | Those rows have completed or been cleared. |
| `exportJobItems` table (`schema.ts`), `dataExport:recordSnapshotPage`, `getExportCardsPage` and `deleteJobItemsPage`, their allowlist entries, the row fallback in `apps/files-worker/src/workflows/export.ts`, the `deleteJobItemsPage` call in the maintenance workflow's export cleanup, and the `exportJobItems` read in `accountDeletion/batch.ts` | Exports now keep their snapshot in workflow step state. Runs that snapshotted into rows before, or while Convex lacked `getExportSnapshotPage`, still read and drain them; rows a failed drain left behind go when a ready export expires, or with the account. | Every export run started before the Convex deploy has ended (a few days after it), and `exportJobItems` is empty in production. |
| `cards.placeholderHash`, `derivativeVersion`, `derivativeCheckedAt` (`schema.ts`) | Stored rows may still hold them. No code reads or writes them. | A backfill unsets them on every card; then drop them from the schema. |
| `pendingUploadCleanupStates` table (`schema.ts`) | Production may still hold the cursor rows of the hourly pending-upload sweep, which R2 event notifications and the Files Worker's weekly sweep replaced. No code reads or writes it. | The table is empty in every deployment (clear it from the dashboard if not); then drop it from the schema. |
| `adminDailySnapshot` in `packages/convex/telemetry/crons.ts` | The Convex cron that ran the admin snapshot before the Files Worker did; a firing already queued at deploy time still finds it. It now only queues the Worker's snapshot. | The backend deploy that removed the cron from `crons.ts` has run a day. |
| `LEGACY_ONBOARDING_CARD_CONTENTS` (`card/defaultCards.ts`) | Admin stats recognise onboarding cards created before they were marked. | Those cards are backfilled with the current marker. |
| Raycast `apiKey` preference (`apps/raycast/src/lib/preferences.ts`) | People who pasted an API key before browser sign-in existed. | Raycast drops API-key sign-in. |
| CLI credentials without a `binding` (`apps/cli/src/runtime.ts`, `legacy-logout.test.ts`) | Credential files saved before the CLI recorded which server issued them. | Those tokens have expired everywhere (refresh tokens included). |
| `emitCardOutcome`, `emitUserCreated` and `emitCardProcessingFailed` in `packages/convex/telemetry/events.ts` | Jobs mutations scheduled before their events moved to the workflow dispatch outbox. Nothing schedules them now. | The deploy that stopped scheduling them has run in production for a day (scheduled jobs run within seconds). |
| Row staging for imports: `dataImport` `insertItems`, `getPendingItems`, `createPendingBatch`, `failItems`, `setExtractedFile`, their `workflows/rpcAllowlist.ts` entries, and the Files Worker's `indexPage` / `importBatches` path in `src/workflows/import.ts` | Imports queued before `importJobs.stagedItems`, which keep staging every item as an `importJobItems` row until they finish. | No import job without `stagedItems` is still active (imports go stale after six hours, so a day after the deploy is enough). Keep `importJobItems`, `getUnclaimedFileKeysPage`, `deleteItemsPage` and the account deletion code for its rows: failed items still live there. |
| `exif.takenAt` (`imageExifValidator` in `schema/validators/cards.ts`) and the fallback that reads it in the viewer's zone (`formatTakenAt` in `apps/web/src/lib/exif.ts`, `ExifFacts` in `CardFacts.swift`, `Exif` in `Exif.kt`) | Released Apple and Android builds format `takenAt` in the device's zone, and photos processed before `takenAtClock` have only `takenAt`. | Every supported Apple and Android build reads `takenAtClock`, and no image card has `takenAt` without `takenAtClock`. The production backfill (October 2026, since deleted) filled every photo whose file gives a camera clock time; 7 of 18 gave none, so they need another fix (a fresh EXIF read won't help) or the fallback stays. |
| `cards.aiTranscript` in `cardValidator` (`schema/validators/cards.ts`) | Nothing reads or writes the stored field: every transcript is in `cardTextContents`, and the fallbacks that read the card went in the deploy after `moveCardTranscripts` ran. `aiTranscript` stays the name of the transcript in card details and API responses. | The deploy that removed the fallbacks has run in production; then drop the field, and give `buildEmbeddingText`, local search and `withTranscripts` their own `aiTranscript` type instead of picking it from `Doc<"cards">`. |
| `folders.activeCardCount` (`schema.ts`), the fallback to it in `readFolderCardCount` (`packages/convex/folder/folderRows.ts`) and `migration/backfillFolderCardCounts.ts` | Folders made before `folderCardCounts` keep their count on the folder until the backfill copies it into a base row. Card writes no longer change it; new folders write 0. | The backfill has run in production and every folder has a shard-0 `folderCardCounts` row; then drop the fallback and the backfill, make the field optional, and unset it. It ran in October 2026 and left 2 folders without one, both in an account deletion that had stopped partway; they go when that deletion finishes. |
| `tagCountStates` gate in `recomputeTagSummary` (`packages/convex/tag/tagSummary.ts`) and `migration/backfillTagCounts.ts` | Tag rows written before `userTagCounts` lack `isCounted`, so summaries recount `cardSearchTags` until the backfill has counted them and written the ready row. The full recount stays as the repair path. | It has run in production and on the shared dev deployment (October 2026), so their `global` ready rows exist. It is still the only writer of that row, so deleting it now would leave a new deployment (the E2E stack, a self-hosted one) recounting forever. Remove it together with the gate, once tag syncs alone are trusted to keep `userTagCounts` exact. |
| `state.tagGeneration ?? state.generation` in `syncCardSearchTagsBatchHandler` and `restartCardSearchTagSync` (`packages/convex/card/searchSync.ts`) | Tag sync states written before `tagGeneration`, whose rows carry the chain `generation`. | A backfill sets `tagGeneration` from `generation` on every state that lacks it. |
| Legacy-fingerprint reset in `prepareStorageBatch` (`packages/convex/accountDeletionData.ts`) | Account deletions whose storage progress was recorded under the older fingerprint (one card per batch, hashed full rows) restart that batch instead of failing as changed. | Every account deletion started before the deploy has finished (a day after it). |
| Exact-address lookup on `by_user_url_deleted` in `findLiveCardByUrl` (`packages/convex/card/findDuplicateCard.ts`) and the index itself | A card without `cards.urlKey` is found only by its exact address. The production backfill (October 2026, since deleted) keyed every card, so production no longer needs it; the `url-variants` seed pack's `/l/` cards exist to exercise it, and `devSeed/*.ts` reads the index for its seeded-once checks. | Now: drop the fallback, move `devSeed` to `by_user_urlkey_deleted`, give the `url-variants` pack's `/l/` cards a key (or drop them), and drop the index. |
| Exact-address lookup on `by_jobId_and_url` in `dataImport.insertItems` (`packages/convex/dataImport.ts`) and the index | Import items staged before `importJobItems.urlKey` match a repeat in the same job only by address. | Every import job started before the deploy has finished (imports go stale after six hours, so a day after it); then drop the fallback and the index. |
| The 12 `…_created` indexes the `…_saved` ones replaced (`schema.ts`): on `cards` `by_user_deleted_created` and `by_user_deleted_archived_created`, `…_type_created`, `…_favorited_created` and `…_host_created`; on `folderCards` the two `…_cardCreatedAt` ones; on `cardSearchTags` `by_user_tag_deleted_created`, `…_archived_created_v2`, `…_archived_type_v2`, `…_archived_favorited_v2` and `…_archived_type_favorited_v2` | Nothing reads them since roadmap v3 phase 2b moved every reader to the `…_saved` twins. They stay so the Convex code before that deploy, still serving until the deploy finishes, keeps its indexes. `by_created` stays for good: admin, export and backfills read it. | Phase 2b's Convex deploy has run in production for a day; then drop them in their own PR. |
| `savedAt ?? createdAt` and `cardSavedAt ?? cardCreatedAt` wherever a date is read (`savedAtOf` in `shared/search/sort.ts`, `card/searchReads.ts`, `publicApi/search.ts`, the Shuffle date filter in `card/shuffle.ts`), and `cards.savedAt`, `folderCards.cardSavedAt` and `cardSearchTags.cardSavedAt` being optional | A row without its saved date. The production backfill (October 2026, since deleted) gave every card, folder row and tag row one, and every insert writes it, so none should exist. An index read can't fall back: a row without it would sort as the oldest. | A query on production finds no row without it; then make the fields required (a schema change) and read them directly. |
| The `createdAt` anchor in `decodeCursor` (`packages/convex/publicApi/cursors.ts`), and the restart from the first row when a tag operation's saved cursor is refused (`runTagOperationBatchHandler`, `packages/convex/tag/tagOperations.ts`) | `GET /v1/cards` cursors issued before phase 2b name the anchor `createdAt`, and their `page` (like a tag operation's saved cursor) is a position in a `…_created` index the `…_saved` read refuses. An old page-only list cursor can't be resumed and answers 400 `INVALID_INPUT`. | A day after phase 2b's Convex deploy, when no client still holds such a cursor and every tag operation started before it has finished. |
| The resend without `aiLanguage` in `saveCardAi` (`apps/files-worker/src/workflows/cardProcessing/aiMetadata.ts`) | The Files Worker deploys before Convex: until Convex has `updateCardAI`'s `aiLanguage` argument, it refuses the whole AI write, so the Worker sends it again without the language. | The Convex deploy that added `cards.aiLanguage` has run in production (and on the dev deployment). |
