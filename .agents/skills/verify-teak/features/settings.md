# Settings

Settings is pages under `/settings`, listed in the nav "Settings pages" at 768 px and wider: **Account** (`/settings`), **Plan** (`/settings/plan`), **Appearance** (`/settings/appearance`), **Integrations** (`/settings/integrations`), **Security** (`/settings/security`) and **Import & export** (`/settings/data`). Every page is a list of rows (name left, control right) grouped into bordered cards. API keys are created, shown once, and revoked on Integrations.

## Sub-features

- `settings-open` opens `/settings` (document title "Settings · Teak"): heading "Settings", the page heading "Account", the region "Signed in as" with the account's name and email, and the button "Sign out".
- `settings-account` shows on Account the row "Plan" (free: link "Upgrade to Pro" to `/settings/plan`; Pro: a link to Plan with the badge "Pro") and the row "Cards used" with its progressbar ("N of 200 cards", "M cards left"; on Pro, "N cards saved, with no limit."); at 768 px and wider, the button "Keyboard shortcuts" (showing `?`), which opens the dialog "Keyboard shortcuts"; and the nav "Help and resources" with links "Docs", "Changelog" and "Help" (new tabs) and the row "Version". Apps and extensions are on Integrations only.
- `settings-overview` lists every other page in the nav "All settings" below 768 px (instead of "Settings pages"), each with its summary: Plan "Free Plan · N of 200 cards", Appearance "System theme · English", Integrations "Save by email off · no API keys", Security "N devices signed in", Import & export "Bring cards in, or take them with you" (or "Export in progress", "Export ready to download", "Last export <date>"). Summaries wrap, never ending in "…"; the email in "Signed in as" wraps only before its `@`.
- `settings-nav` moves between pages from the nav "Settings pages" (current one `aria-current="page"`; long labels such as "Import & export" in German or `?__locale=en-XA` wrap, not cut), and back to Account by the header breadcrumb link "Settings". The level-1 heading reads "Settings › Appearance" and the document title, announced after the move, "Appearance · Settings · Teak" in the UI's language. At 390 px the nav is hidden; Account's list is the way in.
- `app-shell-skip` makes "Skip to content" the first Tab stop on every signed-in page (hidden until focused); Enter moves focus past the sidebar without changing the URL.
- `focus-ring` draws a dark navy ring (pale blue in dark mode) around the focused control at once, no fade-in, visible on white and on red buttons such as "Upgrade to Pro", "Create key" and "Start export".
- `settings-shortcut` opens `/settings` with `G` then `S` from any page; the command palette's group "Settings" opens each page ("Settings: Plan" …).
- `settings-theme` switches system, light and dark from the segmented control "Theme" on Appearance ("Use system theme", "Use light theme", "Use dark theme"), beside the row "Language". Unselected options' text meets 4.5:1 on the grey track in light and dark (axe `color-contrast`).
- `settings-devices` lists signed-in devices on Security in the list "Devices", "This device" first, each named in the UI's language from its browser and system ("Chrome on Linux", German "Chrome unter Linux", "Teak browser extension", "Unknown device") with its sign-in time and, once used since, "Last active <date>", 25 at a time with "Show more devices". Each, or all but this one ("Sign out other devices"), can be signed out after a confirmation.
- `settings-data-scope` loads only what a page shows: devices (from WorkOS) on Security, API keys on Integrations, the last export on Import & export, all three on Account (for its summaries), none on Plan and Appearance. Loaded data stays loaded across Settings pages.
- `settings-apps` lists on Integrations, in section "Apps and extensions", links "Chrome", "Firefox", "iPhone & Mac", "Android" and "Raycast" (each named "… Get (opens in a new tab)", to the Chrome Web Store, Firefox Add-ons, the App Store, Google Play and the Raycast Store), and the link "All apps" to teakvault.com/apps.
- `settings-api-key-create` creates a key on Integrations, shown once, with "Copy". The optional textbox "Name for a new key (optional)" (its label focuses it) names it (up to 64 characters) in the list "API keys". With no keys the panel reads "No API keys yet. Create one to use the API, the CLI, Raycast or an MCP client."
- `settings-api-key-revoke` revokes one key after a confirmation; it stops working. Focus moves to the next key's "Revoke …" (the one above if last, "Create key" if none are left). Other new keys' reveals stay.
- `settings-api-key-regenerate` replaces a key after a confirmation.
- `settings-plan` shows on Plan the row "Current plan" with its badge ("Free Plan" or "Pro") and the progressbar "Cards used" and, on the free plan, the section "Upgrade to Pro" with "$99 / year" (first, with the badge "Best value • Save 57%") and "$19 / month", the list "Everything in Pro", and "Continue to checkout". On Pro: the card "Teak Pro · Everything, unlimited.", the row "Billing" with "Manage subscription", and "Included in your plan" instead.
- `settings-delete-account` asks for the phrase "delete account" in a field that starts empty each time.
- `settings-legacy-link` sends an old `/settings?dialog=import` (or `export`) link to `/settings/data#import` (or `#export`) before the page renders: a page load gets a server redirect (`curl -sI` with a signed-in cookie shows a 307 with that `location`), and an in-app link never shows Account first. Any other `dialog` value goes to `/settings`.
- `not-found` shows "Page not found" and link "Go to your cards" for any unknown URL, in the chosen theme.

## How to get to it (user POV)

- The sidebar link "Settings" (tooltip and hover hint `G S`), `G` then `S`, or `/settings`.
- The nav "Settings pages", or, below 768 px, a link in Account's list "All settings".
- Settings → Security for devices and connected apps; Integrations for API keys.
- Settings → Plan, or any "Upgrade" (the card-limit prompt, the extension popup), lands on `/settings/plan`.
- Settings → Security → section "Delete account" → "Delete your account" → dialog "Delete account".
- Any unknown URL, such as `/does-not-exist-xyz`.
- Command palette: "Settings", "Settings: <page>", "Toggle theme", "Import", "Export".

## Driving it with e2e MCP

Preconditions:

- Signed in ([sign-in](./sign-in.md)).
- No key named for this run exists; an account holds at most 10 active keys.

Steps:

- **Open.** `tap` link "Settings" (foot of the sidebar): the `settings-open` content shows. At 1440 px the nav "Settings pages" is beside them, with no "All settings"; at 390 px "All settings" lists the five other pages with summaries (each a pulsing bar until its data loads).
- **Account extras.** On `/settings` at 1440 px, check the `settings-account` rows; "Upgrade to Pro" goes to `/settings/plan` (go `back`). `tap` "Keyboard shortcuts": its dialog opens; `press` "Escape" and focus returns to the button. Scroll the page sideways at 800 px: it doesn't move.
- **Navigate.** In "Settings pages", `tap` "Appearance": heading "Appearance" (level 2), the link is `aria-current="page"`, the header reads "Settings › Appearance". The header link "Settings" returns to `/settings`. `g` then `s` from `/` opens `/settings`.
- **Back keeps the library's place.** At 1280×500 on `/`, `window.scrollTo(0, 600)` (the seeded library is about 1500 px tall). `tap` "Settings", then go `back`: `window.scrollY` reads 600 again once the cards are in (poll up to 5 s), not 0, though the library first renders its loading frame. A window made taller on Settings lands as far down as the page allows; a scroll or key before the cards arrive stays put.
- **Theme.** On Appearance, `tap` "Use dark theme": it becomes pressed and the page turns dark (screenshot). Account's Appearance summary reads "Dark theme · English". `tap` "Use system theme" to restore. The theme lives only in this browser, not the backend.
- **Devices.** On `/settings/security`, region "Devices" holds the list "Devices", first item "This device" with button "Sign out <device> (this device)"; each reads "Signed in <date>, <time>", plus " · Last active <date>, <time>" once used since. Sign in from another browser context for a second item. `tap` its "Sign out <device>": alert dialog "Sign out <device>?" names its sign-in time, with "Cancel" and "Sign out". `tap` "Cancel"; the device stays. "Sign out other devices" opens alert dialog "Sign out all other devices?" ("This device stays signed in."); `tap` "Cancel". Confirm only on a throwaway local account: the status reads "Signed out N other devices.", only "This device" stays, and this browser is still signed in. Never confirm either on the shared account. With more than 25 devices, `tap` "Show more devices": the rest load below, the button goes, and the total matches the account's WorkOS sessions (no alert "Could not load devices. Please try again."). The seeded account has one or two sessions; for a second page, sign in over 25 times with WorkOS's password sign-in, then revoke those sessions. In Deutsch ([language](./language.md)) names read "Firefox unter macOS" and the like. Region "Connected apps" follows, then section "Delete account".
- **Data per page.** Record the sync socket's queries and actions (`page.routeWebSocket` on `convex.cloud/api/*/sync`: `ModifyQuerySet` adds and `Action` udfPaths). A full load of `/settings/plan` or `/settings/appearance` asks for none of `securitySessions:listAuthkitSessions`, `apiKeys:listUserApiKeys` and `dataExport:getLatestExport`; `/settings/integrations` only the keys, `/settings/security` only the devices, `/settings/data` only the export, `/settings` all three. Moving Plan → Security → Plan → Security asks WorkOS once.
- **API-key label.** On `/settings/integrations`, click the label "Name for a new key (optional)": its empty textbox gets focus (no key is created).
- **Create a key.** On `/settings/integrations` with no keys, region "API keys" shows the `settings-api-key-create` empty text. `type` "verify-teak run" into "Name for a new key (optional)". In region "API keys" (description "Up to 10 keys.", linking the API docs), `tap` "Create key" (or Enter): the list shows "verify-teak run" above the masked key and the textbox empties. The status reads "API key created. Copy it now; it is only shown once.", read-only textbox "New API key" and "Copy" appear, and the list gains `teakapi_secret_live_<prefix>_••••••••` with "Regenerate …" and "Revoke …". Don't read the textbox's value into notes, commands or kept screenshots.
- **Regenerate.** `tap` "Regenerate teakapi_secret_live_<prefix>_••••••••, created <date>" for that key, then "Regenerate key" in alert dialog "Regenerate this API key?". The status reads "API key regenerated. Copy the new key now." and "New API key" shows the new key.
- **Revoke keeps other reveals.** `tap` "Create key" twice: two "New API key" textboxes show, newest first. `tap` "Revoke …" for the older key: alert dialog "Revoke this API key?"; Escape or "Cancel" keeps the key and returns focus to that button. `tap` it again, then "Revoke key": status "API key revoked.", the item goes, focus is on the remaining key's "Revoke …" (not the page body), and the newer key's textbox stays.
- **Revoke all asks first.** "Revoke all keys" opens alert dialog "Revoke all API keys?"; `tap` "Cancel". Never confirm it on the shared account (it kills other runs' keys).
- **Revoke what you made.** Before leaving, revoke every key this run created here: "Revoke teakapi_secret_live_<prefix>_••••••••, created <date>", then "Revoke key" (unnamed keys show only the prefix; `observe` the list for the current prefix after a regenerate). Status "API key revoked.", and the item goes.
- **Prove a revoked key stops working.** Mint with `bun .agents/skills/verify-teak/scripts/api-key.ts mint`; it's listed on Integrations as "verify-teak" (proving API-made keys appear). `bun …/api-key.ts check` prints 200. `tap` "Revoke verify-teak, teakapi_secret_live_<prefix>_••••••••, created <date>", then "Revoke key": status "API key revoked.". `bun …/api-key.ts check` prints 401 within about 15 s; then `bun …/api-key.ts revoke` clears the saved file.
- **Plan.** On `/settings/plan`, the progressbar "Cards used" reads "N of 200 cards" with "M cards left" (N matches Account's). Section "Upgrade to Pro" shows "$19 / month", "$99 / year" (selected) and "Best value • Save 57%", the feature "iOS, Mac & Android apps" (sentence case), and "Continue to checkout", which you don't press.
- **Delete account (don't).** On `/settings/security`, `tap` "Delete your account", `type` "delete acc" into textbox "Type "delete account" to proceed", `press` "Escape", and reopen: the textbox is empty and "Delete account" disabled. `press` "Escape"; focus returns to "Delete your account".
- **Focus and skip link.** On `/settings` in light mode, `press` Tab: link "Skip to content" appears top left; Enter, then Tab: focus lands on "Sign out", not the sidebar. Tab to "Upgrade to Pro": a dark ring shows at once around the red button. Screenshot it, and in dark mode.
- **Announced titles.** After `tap` "Appearance" in "Settings pages", the document title reads "Appearance · Settings · Teak" and the level-1 heading "Settings Appearance"; in Deutsch, "Darstellung · Einstellungen · Teak".
- **Phone.** At 390 px in German, "All settings" shows each summary in full ("Per E-Mail speichern aus · keine API-Schlüssel" wraps), and `first-last@example.com` breaks only before `@`.
- **Old links.** `/settings?dialog=export` becomes `/settings/data#export`, showing region "Export".
- **Not found.** `navigate` to `/does-not-exist-xyz`: heading "Page not found" and link "Go to your cards" (to `/`), on the theme's background (also dark with "Use dark theme" while the system is light). Title "Page not found · Teak".

## Gotchas

- Revoke, regenerate, "Revoke all keys", device "Sign out" and app "Disconnect" act only on their alert dialog's confirm button. "Revoke all keys" also kills the key `scripts/api-key.ts` minted for other recipes: run those first, or mint again.
- The key list updates before the revoke or regenerate call returns; wait for the status ("API key revoked.", "API key regenerated. …") before reading "New API key" textboxes.
- Never copy the full key out of the page: agent safety checks (Claude Code's auto mode) block using a key read off the screen, and a key in notes or video leaks. Prove keys work with `scripts/api-key.ts`, which keeps the key in its own process.
- Screenshots and video of Integrations right after "Create key" show the full key: keep them out of PRs, or revoke the key first and say so.
- Unnamed Settings keys are named "Default API key", which the list hides. Names are cut at 64 characters.
- "Sign out other devices" signs out up to 20 devices per press; with more, the status says some are still signed in, and pressing a minute later finishes.
- "Sign out <device> (this device)" in Devices ends this session.
- Creating and regenerating keys share one rate limit, five a minute ("Too many API keys created. Try again in a minute."). A sixth regenerate in the minute alerts "Could not update your API keys. Please try again." and keeps the old key; space regenerate drives a minute apart.
