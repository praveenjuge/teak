# Settings

Settings is a set of pages under `/settings`, listed in the nav "Settings pages" beside the content at 768 px and wider: **Account** (`/settings`), **Plan** (`/settings/plan`), **Appearance** (`/settings/appearance`), **Integrations** (`/settings/integrations`), **Security** (`/settings/security`) and **Import & export** (`/settings/data`). Every page is a list: each setting's name on the left and its control on the right, grouped into bordered cards (a small caption above a card where it has several rows), and each page in the nav has a colored icon tile. Account shows who is signed in with sign-out, the plan and cards used, the keyboard shortcuts, and a list of Docs, Changelog, Help and Version above the signed note; on phones it also lists every other page with its summary. Security ends with the delete-account section. API keys are created here (Integrations), shown once, and revoked here.

## Sub-features

- `settings-open` opens `/settings` (document title "Settings · Teak"): heading "Settings", the page heading "Account", the region "Signed in as" with the account's name and, under it, its email as text, and the button "Sign out".
- `settings-account` shows on Account, at every width, a card with the row "Plan" (on the free plan, its link "Upgrade to Pro" to `/settings/plan`; on Pro, a link to Plan with the badge "Pro") and the row "Cards used" with its progressbar ("N of 200 cards", "M cards left" under the label; on Pro, "N cards saved, with no limit."); at 768 px and wider, the row "Keyboard shortcuts" whose button "Keyboard shortcuts" (showing `?`) opens the dialog "Keyboard shortcuts"; and the nav "Help and resources" with links "Docs", "Changelog" and "Help" (each opens a new tab) and the row "Version". The apps and extensions are on Integrations only.
- `settings-overview` lists every other page in the nav "All settings" below 768 px (wider screens have the nav "Settings pages" instead), each a link with its summary: Plan "Free Plan · N of 200 cards", Appearance "System theme · English", Integrations "Save by email off · no API keys", Security "N devices signed in", Import & export "Bring cards in, or take them with you" (or "Export in progress", "Export ready to download", "Last export <date>"). Summaries wrap instead of ending in "…", and the email in "Signed in as" wraps only before its `@`, never at a hyphen.
- `settings-nav` moves between pages from the nav "Settings pages" (the current one has `aria-current="page"`; long labels such as "Import & export" in German or `?__locale=en-XA` wrap instead of being cut), and from a page back to Account by the header breadcrumb link "Settings". The sub-page's name is part of the page's heading (level 1 "Settings › Appearance"), and the document title is "Appearance · Settings · Teak" in the UI's language, which is what a screen reader announces after the move. At 390 px the nav is hidden; Account's list is the way in.
- `app-shell-skip` makes "Skip to content" the first Tab stop on every signed-in page (hidden until focused); Enter moves focus to the page past the sidebar, without changing the URL.
- `focus-ring` draws a dark navy ring (light pale blue in dark mode) around the focused control at once, with no fade-in, visible on white and on red buttons such as "Upgrade to Pro", "Create key" and "Start export".
- `settings-shortcut` opens `/settings` with `G` then `S` from any page; the command palette's group "Settings" opens each page ("Settings: Plan" …).
- `settings-theme` switches system, light and dark from the segmented control "Theme" on Appearance (buttons "Use system theme", "Use light theme", "Use dark theme"), in the same card as the row "Language".
- `settings-devices` lists signed-in devices on Security in the list "Devices", "This device" first, each named in the UI's language from its browser and system ("Chrome on Linux", German "Chrome unter Linux", "Teak browser extension", "Unknown device") with its sign-in date and time and, once it has been used since, "Last active <date>", 25 at a time with "Show more devices" for the rest. Each can be signed out after a confirmation, and "Sign out other devices" signs out every device but this one after its own confirmation.
- `settings-api-key-create` creates a key on Integrations, shown once, with "Copy". The optional textbox "Name for a new key (optional)" names it (up to 64 characters), and the name shows in the list "API keys". With no keys the panel reads "No API keys yet. Create one to use the API, the CLI, Raycast or an MCP client."
- `settings-api-key-revoke` revokes one key after a confirmation, and the key stops working. Focus moves to the next key's "Revoke …" button (the one above when it was last, "Create key" when none are left). Other new keys' one-time reveals stay.
- `settings-api-key-regenerate` replaces a key with a new one after a confirmation.
- `settings-plan` shows on Plan the row "Current plan" with its badge ("Free Plan" or "Pro") and the progressbar "Cards used" ("N of 200 cards", "M cards left") and, on the free plan, the section "Upgrade to Pro" with "$99 / year" (first, with the badge "Best value • Save 57%") and "$19 / month", the list "Everything in Pro", and "Continue to checkout". On Pro it opens with the card "Teak Pro · Everything, unlimited.", has the row "Billing" with "Manage subscription", and lists "Included in your plan" instead.
- `settings-delete-account` asks for the phrase "delete account"; the field starts empty every time the dialog opens.
- `settings-legacy-link` sends an old `/settings?dialog=import` (or `export`) link to `/settings/data#import` (or `#export`).
- `not-found` shows "Page not found" with a link "Go to your cards" for any unknown URL, in the chosen theme.

## How to get to it (user POV)

- The sidebar link "Settings" (tooltip and hover hint `G S`), `G` then `S`, or `/settings`.
- The nav "Settings pages", or, below 768 px, a link in Account's list "All settings".
- Settings → Security for devices and connected apps; Settings → Integrations for API keys.
- Settings → Plan, or any "Upgrade" in the app (the card-limit prompt, the extension popup), lands on `/settings/plan`.
- Settings → Security → the section "Delete account" → button "Delete your account" → dialog "Delete account".
- Any unknown URL, such as `/does-not-exist-xyz`.
- Command palette: "Settings", "Settings: <page>", "Toggle theme", "Import", "Export".

## Driving it with e2e MCP

Preconditions:

- Signed in ([sign-in](./sign-in.md)).
- No key named for this run exists. An account holds at most 10 active keys.

Steps:

- **Open.** `tap` link "Settings" (at the foot of the sidebar). Heading "Settings", the section "Signed in as" with the account email, and the button "Sign out" are shown. At 1440 px the nav "Settings pages" is beside them and the nav "All settings" is not shown; at 390 px "All settings" lists "Plan", "Appearance", "Integrations", "Security" and "Import & export" with their summaries (a summary is a pulsing bar until its data loads).
- **Account extras.** On `/settings` at 1440 px: the progressbar "Cards used" reads "N of 200 cards" with "M cards left", and link "Upgrade to Pro" goes to `/settings/plan` (go `back`). The nav "Help and resources" has links "Docs", "Changelog" and "Help" and the row "Version". `tap` button "Keyboard shortcuts": dialog "Keyboard shortcuts" opens; `press` "Escape" and focus returns to the button. Scroll the page sideways at 800 px: it doesn't move.
- **Navigate.** In the nav "Settings pages", `tap` "Appearance": heading "Appearance" (level 2), the link is `aria-current="page"`, and the header reads "Settings › Appearance". `tap` the header link "Settings": back on `/settings`. `press` `g` then `s` from `/`: `/settings` opens.
- **Theme.** On Appearance, `tap` button "Use dark theme". It becomes pressed (filled segment) and the page turns dark (take a screenshot). `tap` "Use system theme" to restore. The theme lives only in this browser, so there's nothing to read back from the backend. Account's Appearance summary follows ("Dark theme · English").
- **Devices.** `navigate` to `/settings/security`. Region "Devices" holds the list "Devices", whose first item is marked "This device", with a button "Sign out <device> (this device)"; each item reads "Signed in <date>, <time>", or "Signed in <date>, <time> · Last active <date>, <time>" once used since. Sign in a second time from another browser context to get a second item. `tap` another device's "Sign out <device>": alert dialog "Sign out <device>?" names its sign-in time, with "Cancel" and "Sign out". `tap` "Cancel"; the device stays listed. `tap` "Sign out other devices": alert dialog "Sign out all other devices?" says "This device stays signed in."; `tap` "Cancel". Confirm it only on a throwaway local account: the status then reads "Signed out N other devices.", only "This device" stays listed, and this browser is still signed in. Never confirm either on the shared account. With more than 25 devices the list ends in button "Show more devices": `tap` it and the rest load below, the button goes away, and the total matches the account's WorkOS sessions (no alert "Could not load devices. Please try again."). The seeded account has one or two sessions; to drive the second page, sign in to it more than 25 times through WorkOS's password sign-in, and revoke those sessions afterwards. Switch the language to Deutsch ([language](./language.md)): the names read "Firefox unter macOS" and the like. Region "Connected apps" is below it, then the section "Delete account".
- **Create a key.** `navigate` to `/settings/integrations`. With no keys, region "API keys" reads "No API keys yet. Create one to use the API, the CLI, Raycast or an MCP client." `type` "verify-teak run" into textbox "Name for a new key (optional)". In region "API keys" (its description says "Up to 10 keys." and links to the API docs), `tap` button "Create key" beside the title (or `press` Enter in the textbox). The list "API keys" shows the name "verify-teak run" above the masked key, and the textbox is empty again. The status reads "API key created. Copy it now; it is only shown once.", a read-only textbox "New API key" and a button "Copy" appear, and the list gains `teakapi_secret_live_<prefix>_••••••••` with "Regenerate …" and "Revoke …" buttons. Don't read the textbox's value into notes, commands or screenshots you keep.
- **Regenerate.** `tap` "Regenerate teakapi_secret_live_<prefix>_••••••••, created <date>" for that key. Alert dialog "Regenerate this API key?" opens; `tap` its "Regenerate key". The status reads "API key regenerated. Copy the new key now." and a "New API key" textbox shows the new key in place of the old one's.
- **Revoke keeps other reveals.** `tap` "Create key" twice: two "New API key" textboxes show, newest first. `tap` "Revoke …" for the older key: alert dialog "Revoke this API key?" opens, and Escape or "Cancel" closes it with the key still listed and focus back on that "Revoke …" button. `tap` it again, then the dialog's "Revoke key". The status reads "API key revoked.", the item disappears, focus is on the remaining key's "Revoke …" button (not the page body), and the newer key's textbox is still shown.
- **Revoke all asks first.** `tap` "Revoke all keys": alert dialog "Revoke all API keys?" opens. `tap` "Cancel". Never confirm it on the shared account (it kills every key, including other runs').
- **Revoke what you made.** Before leaving the page, revoke every key this run created here: "Revoke teakapi_secret_live_<prefix>_••••••••, created <date>", then "Revoke key" in the confirmation (keys made in Settings show no name, only the prefix; `observe` the list for the current prefix after a regenerate). The status reads "API key revoked." and the item disappears.
- **Prove a revoked key stops working.** Mint a key with `bun .agents/skills/verify-teak/scripts/api-key.ts mint`; it's listed on Integrations as "verify-teak", which also proves a key made through the API appears in Settings. `bun …/api-key.ts check` prints 200. `tap` "Revoke verify-teak, teakapi_secret_live_<prefix>_••••••••, created <date>", then "Revoke key" in the confirmation: the status reads "API key revoked." and the item disappears. `bun …/api-key.ts check` prints 401 within about 15 s; then `bun …/api-key.ts revoke` clears the saved file.
- **Plan.** `navigate` to `/settings/plan`. The progressbar "Cards used" reads "N of 200 cards" with "M cards left" (N matches Account's card count). The section "Upgrade to Pro" shows "$19 / month", "$99 / year" (selected) and "Best value • Save 57%", the feature "iOS, Mac & Android apps" (features in sentence case), and the button "Continue to checkout". Don't continue to checkout.
- **Delete account (don't).** On `/settings/security`, `tap` "Delete your account". `type` "delete acc" into textbox "Type "delete account" to proceed", `press` "Escape", and open it again: the textbox is empty and "Delete account" is disabled. `press` "Escape"; focus is back on "Delete your account".
- **Focus and skip link.** On `/settings` in light mode, `press` Tab once: link "Skip to content" appears top left; `press` Enter, then Tab: focus lands in the page (the "Sign out" button), not the sidebar. `press` Tab to "Upgrade to Pro": a dark ring shows at once around the red button. Screenshot it, and the same in dark mode.
- **Announced titles.** `tap` "Appearance" in the nav "Settings pages": the document title reads "Appearance · Settings · Teak" and the level-1 heading reads "Settings Appearance". With Deutsch chosen it reads "Darstellung · Einstellungen · Teak".
- **Phone.** At 390 px in German, Account's list "All settings" shows each summary in full (Integrations "Per E-Mail speichern aus · keine API-Schlüssel" wraps to a second line), and an email such as `first-last@example.com` breaks only before `@`.
- **Old links.** `navigate` to `/settings?dialog=export`: the URL becomes `/settings/data#export` and region "Export" is shown.
- **Not found.** `navigate` to `/does-not-exist-xyz`. Heading "Page not found" and link "Go to your cards" (to `/`) show, on the theme's background (also with "Use dark theme" pressed while the system is light). The document title is "Page not found · Teak".

## Gotchas

- Revoke, regenerate, "Revoke all keys", device "Sign out" and app "Disconnect" each open an alert dialog first; the action runs only on its confirm button. "Revoke all keys" also kills the key `scripts/api-key.ts` minted for other recipes. Run the API recipes first, or mint again afterwards.
- The key list updates before the revoke or regenerate call returns. Wait for the status text ("API key revoked.", "API key regenerated. …") before reading the "New API key" textboxes.
- The full key is shown only once. Never copy it out of the page: agent safety checks (Claude Code's auto mode) block using a key read off the screen, and a key in notes or video leaks. Prove keys work with `scripts/api-key.ts`, which keeps the key inside its own process.
- Screenshots and video of Integrations right after "Create key" show the full key. Keep them out of PRs, or revoke the key first and say so.
- Keys made in Settings without a name are named "Default API key", which the list hides; a named key shows its name. Names are cut at 64 characters.
- "Sign out other devices" signs out up to 20 devices per press; with more, the status says some are still signed in, and a press a minute later finishes.
- "Sign out <device> (this device)" in Devices ends this session.
- Creating and regenerating keys share one rate limit, five a minute ("Too many API keys created. Try again in a minute."). A sixth regenerate within the minute shows the alert "Could not update your API keys. Please try again." and leaves the key as it was; space regenerate drives a minute apart.
