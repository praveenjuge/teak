# API, CLI and MCP

People and agents use Teak without the web app through the public REST API, the `teak` CLI and the MCP server, all authenticated with an API key. A card created through any of them shows up everywhere else.

## Sub-features

- `api-auth` rejects a missing or revoked key with 401; `GET /v1/me` answers a valid one.
- `api-cards` creates, gets, lists, searches, trashes, restores and permanently deletes cards (`/v1/cards`), and runs bulk operations (`/v1/cards/bulk`) whose items follow single-card rules (tag cleaning; a blank `url`, blank `content` on a non-text card, a file `cardType` without an upload even with a `url`, any edit in Trash but `restore` and `delete` fail it) and fail with `INVALID_INPUT` on an unknown or wrong-typed field (`"tags":"design"`, `"notes":5`) or an empty `update`. See **REST bulk rules** and **REST bulk fields and AI tags**.
- `api-tag-ops` renames, merges and deletes tags (`/v1/tags/rename|merge|delete`, MCP's tag tools); an existing tag may be up to 256 characters, a new name up to 64.
- `api-duplicate` finds a saved link under any address (`GET /v1/cards/duplicate`, `teak cards duplicate`, MCP's `teak_v1_check_duplicate_url`, the extension's badge): `http`/`https`, a leading `www.`, the host's case, a default port, one trailing slash, a fragment and `utm_*`, `fbclid` and `gclid` don't count; other parameters and their order, the path's case, a `#/` or `#!` route and any other port (`http://…:443`) do. Archived cards match, Trash doesn't; of two, the newest is returned. A keyless card (the pack's `/l/` cards) matches only its exact address.
- `api-resave` saves a link already in Teak (as `url`, or `content` that is only the link, in any variant `api-duplicate` matches) without a second card: `POST /v1/cards` answers 200 `status: "created"`, `resaved: true` and the existing card, saved again and out of Archive; tags and notes sent with it are ignored. **Re-save** drives every case. Every card in the API, and in an export's `cards.json`, has `savedAt`.
- `cli-changes` prints `teak cards changes` as card lines, then `deleted <id>` lines, and `Next page: --next …` on stderr while pages remain.
- `api-tag-limits` trims tags, keeps one per case variant, and answers 400 `INVALID_INPUT` to over 100 tags or a tag over 64 characters, on create, update and bulk.
- `api-uploads` saves an uploaded file as a card from any client (`POST /v1/uploads`, `PUT` to its `uploadUrl`, then a create with its `fileKey`; MCP's `teak_v1_create_card`, the CLI and Raycast too).
- `api-transcripts` returns an audio card's `aiTranscript` from `GET /v1/cards/<id>`; list and search need `include=processing`.
- `api-limits` takes `limit` on `GET /v1/cards` and `/v1/cards/changes` as a whole number from 1 (default 50), returns 100 for anything larger (the OpenAPI `maximum`), and refuses the rest (**REST limit**). `similarTo` other than one card id (`<id> design`) answers `400 INVALID_INPUT`; a `sort=relevance` cursor sent to a plain listing answers `400` "Query parameter `cursor` is invalid" instead of restarting. An unknown `type`, `style` or `hue` (`type=bogus`, `style=glossy`, `hue=beige`) answers `400 INVALID_INPUT` naming the accepted values ("Query parameter `type` must be one of: text, link, …", "Query parameter `hue` is not one Teak knows. Use one of: red, …"); a hue alias such as `violet` is accepted.
- `cli-cards` runs `auth status`, `cards create`, `cards search`, `cards list` and `cards delete`.
- `mcp-tools` handles `initialize` (with icons), `tools/list` and `tools/call`. A call's `content` is a one-line summary ("1 card", never "1 cards"), then JSON equal to `structuredContent` (card-view hosts give the model only `content`); list and search tools return each card's `content` regardless of `include`. A batch of only notifications gets `202` with no body, at the edge and in Convex.
- `mcp-validation` refuses unknown arguments (naming the accepted ones), says plainly what is wrong with an argument, and refuses non-Teak ids; a route word (`changes`) as an id still names a card. A message without an `id` gets no answer, one with an id under `notifications/` gets `-32601`, and batch messages are answered one by one.
- `api-errors` answers a wrong method on a `/v1/` path with JSON `405 METHOD_NOT_ALLOWED` and `Allow`, an unknown path with JSON `404 NOT_FOUND`, both with `Access-Control-Allow-Origin`; `PATCH` names the refused field; `content` over 512 KiB or `notes` over 256 KiB answer `400 CONTENT_TOO_LARGE` (in bulk, the item fails with it); an extra segment under a route (`/v1/highlights/<id>/x`) is `404`, not `405`; a card path served for other methods (`GET /v1/cards/<id>/save-pdf`, `GET …/done`) is `405` with `Allow`.
- `api-folder-rules` sets a manual folder's rules (`autoTags`, `autoFileQuery`, `autoFileEnabled`) through `POST`/`PATCH /v1/folders`, `teak folders rules`, `create --auto-tag --auto-file` and MCP's folder tools. Saving starts a rule run over existing cards (`ruleRunId`), read with `GET /v1/folders/<id>/rule-runs/<runId>` (`teak folders rule-run --wait`, `teak_v1_get_folder_rule_run`) and undone with `POST …/undo` (`teak folders undo-rule-run`, `teak_v1_undo_folder_rule_run`). New matching cards are filed once AI tags are written; one removed by hand stays out through a refresh. `like:`/`mood:`, 11 tags or rules on a smart folder answer 400, an unknown run 404, a wrong method on a run 405, a 51st folder with rules 409 `RULE_LIMIT`.
- `cli-empty` explains an empty listing on stderr (empty stdout, exit 0): "No favorite cards yet." for `teak cards favorites` (likewise `search`, `trash`, `tags list`, `folders list`, `highlights list`), "No cards match those filters." with a filter; `--json` prints the empty list.
- `cli-reliability` keeps `teak add --url` off stdin; refuses a missing `add --file <path>` or `cards bulk --file <path>` (exit 2 "no file at …", no request, no text card), keeps the case typed in `teak tags add <id> GraphQL`, saves piped text as text, sends an `Idempotency-Key` with `add` and `bulk`, refuses a non-time `--created-after` (exit 2, no request), and checks `export -o`'s file before exporting.
- `cli-design` follows the CLI design rules (**CLI design**): stdout holds only the answer; errors name what was missing, quote the request id and say what to run next (one JSON line with `--json`, usage errors too). Also: `--all` stops at 10,000 cards, `--since` takes dates and ages, `todo` undoes `done`, every top-level shortcut takes its `cards` command's options, `rm` is `delete` in every group and the old `tags rm` warns, `tags merge|delete --dry-run` change nothing, `--wait` stops at `--timeout`, and `AI_AGENT` or `CI` never prompt, like `CLAUDECODE`.
- `cli-guidelines` keeps the CLI to the [CLI guidelines](https://vercel.com/design/cli) (**CLI guidelines**): saved text and server messages can't send terminal escape sequences (stripped from human output, escaped in JSON), and every error carries a `reason`. Also: a terminal listing's Age counts from `savedAt` (a re-saved link reads `1m`; a pipe's ISO column stays the creation time), a file card shows its title or file name there (piped too), not a blank cell, and a daily update notice shows only to a person at a terminal (`TEAK_NO_UPDATE_CHECK=1` turns it off).

## How to get to it (user POV)

- REST: `https://reminiscent-kangaroo-59.convex.site/v1/...` on dev, with `Authorization: Bearer <key>`; production `https://teakvault.com/api/...`; OpenAPI at `/openapi.json`.
- CLI: `bun apps/cli/src/index.ts …` from the repo root, with `TEAK_API_KEY` and `TEAK_API_URL`.
- MCP: `POST https://reminiscent-kangaroo-59.convex.site/mcp`, JSON-RPC, same bearer key.
- A key: Settings → Integrations → API keys ([settings](./settings.md)), or `scripts/api-key.ts` below.

## Driving it with curl, the CLI and scripts/api-key.ts

Preconditions:

- The dev stack runs (`scripts/api-key.ts` signs in with its seeded account).
- Mint a key and set the environment for the run:

```bash
bun .agents/skills/verify-teak/scripts/api-key.ts mint
export TEAK_API_KEY="$(jq -r .key .agents/.state/verify/api-key.json)"
export TEAK_API_URL=https://reminiscent-kangaroo-59.convex.site SITE=https://reminiscent-kangaroo-59.convex.site
E=.agents/.state/verify/<run-id> && mkdir -p "$E"
```

- **REST saved order.** `sort=newest` and `sort=oldest` follow the last save (`savedAt`), not the first.   - Dry runs. `$T tags rename $M $M-x --dry-run` prints "Would rename … on 2 cards in your library, and on any in Archive and Trash. Nothing changed." and `$T --json tags` still lists `$M`; `echo '[{"cardId":"<id>","isFavorited":true}]' | $T cards bulk favorite --dry-run` prints "Would run favorite on 1 item; each has the fields it needs.", and without `isFavorited` it exits 2 naming the missing field.
  - Agents and batches. `CLAUDECODE=1 $T tags delete $M` exits 2 "add --yes to confirm"; `$T restore <id> cnoexist000000000000000000` prints the restored id, then "1 of 2 cards done; 1 failed." and "Retry the failed ones: teak restore cnoexist…" (rm, restore, archive and unarchive send one `POST /v1/cards/bulk` per 100 ids; a malformed id fails as `INVALID_INPUT`, exit 1, a missing one as `NOT_FOUND`, exit 4).
  - Offline. `$T --help` lists "Exit codes:" with 130; `$T cards list --help` ends with examples; `$T __complete cards unf` prints `unfavorite`; `$T completion zsh | head -1` is `#compdef teak`.
- **CLI guidelines.** With `T` and `M` as above, after `$T add "$M guide" --tags $M` (id `<id>`), save stdout, stderr and exit codes to `$E/cli-guidelines.txt`:
  - Escapes. `$T cards update <id> --notes "$(printf 'x \033]0;owned\007 y')"`; `$T cards get <id> | grep -c $'\033'` prints 0 and the line reads `notes: x ]0;owned y`; `$T --json cards get <id> | grep -c '\\u001b'` prints 1.
  - Consent. `CLAUDECODE=1 $T --json folders delete $M-none` and `CLAUDECODE=1 $T highlights delete h_none` each exit 2 with `"reason":"confirmation_required"` (or "add --yes to confirm") and make no request.
  - Reasons and problems. `$T --json cards get` exits 2 with `"reason":"missing_input"`; `$T --json ls --limit zero --type spaceship` exits 2 with a `problems` array of two entries; `$T --json --api-key bad whoami` has `"reason":"login_required"`.
  - Fields. `$T --json --fields id,idd cards get <id>` exits 2 "unknown field \"idd\"; fields here: …" with an empty stdout; `$T --json --fields id,nope fav <id>` exits 0 printing `{"id": "<id>"}` and a `"reason":"unknown_fields"` warning line on stderr.
  - Help. `TEAK_API_KEY= $T help --json | jq -r '.commands[].command' | head -3` lists commands with no key; `$T cards list --help --json | jq .examples`; `$T help --search trash forever | head -1` starts with `teak cards delete (teak rm)`.
  - Filters and files. `$T add "$M other" --tags $M-b` then `$T ls --tag $M --tag $M-b` lists both cards. For a file card `<file-id>`, `$T download <file-id> -o - | wc -c` is the file's size, `$T download <file-id> -o json` exits 2, and `ls -a` shows no `.part` file after `$T download <file-id> -o $E/f --force`.
  - Key and version. `printf '%s' "$TEAK_API_KEY" | TEAK_API_KEY= $T --api-key - whoami` prints the account; `$T -v` and `$T -V` print the same version.
  - Ctrl+C. `$T export --wait & sleep 2; kill -INT $!; wait $!; echo $?` prints "Stopped." and "The export keeps going on Teak. Check on it with: teak export status", then 130 (skip if an export ran this week: the rate limit exits first).
  - Terminal-only output. In a real terminal (`script -qc "$T ls --tag $M" /dev/null`) the listing starts with `ID  Type  Content  Tags  Age`; piped it has no header.
- **Unauthenticated.** `POST $SITE/mcp` and `GET $SITE/v1/me` without a key return 401.
- **Key state.** `bun .agents/skills/verify-teak/scripts/api-key.ts check` prints `GET /v1/me`'s status for the saved key: 200, or 401 once revoked.
- **Cross-surface proof.** An API card's marker finds it in the web app ([find](./find.md)).
- **Cleanup.** Permanently delete every card the run created, then `bun .agents/skills/verify-teak/scripts/api-key.ts revoke` (also clears a key revoked in Settings).

## Gotchas

- Without `TEAK_API_URL`, the CLI silently targets production (`https://teakvault.com/api`). Set it to the dev `.convex.site` origin, with no `/v1` or `/api` suffix; the `/api` prefix exists only behind the production edge proxy.
- `?permanent=true` on a card not in Trash returns 409 `NOT_IN_TRASH`; trash it first.
- Default hybrid search lists related seeded cards too; pass `mode=keyword` (REST, MCP) or `--mode keyword` (CLI) for exact checks.
- A hex color or quoted text is reclassified after creation (poll for the type); `"cardType":"text"` pins it.
- `--permanent` without `--yes` exits 2 outside a terminal or in an agent's shell (`CLAUDECODE`). CLI exit codes: 0 ok, 1 API error or a `--wait` timeout, 2 usage, 3 auth, 4 not found, 5 rate limited, 130 Ctrl+C.
- The live backend may be another branch's push (the doctor says which); backend changes need `bun run dev --detach --push`.
- Past a free account's card limit (for example after seeding `shuffle-partial`), every create answers 400 `CARD_LIMIT_REACHED` before tags are checked; create on an account with room.
- MCP is stateless JSON-RPC (no session id, plain JSON responses) and refuses undeclared tool arguments (`teak_v1_search_cards` takes `q`, not `query`). It needs `Content-Type: application/json` (415 otherwise) and an `Accept` that includes JSON (406 otherwise).
- Never paste the key into notes, PRs or chat; write `<redacted>`.
