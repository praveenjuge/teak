# API, CLI and MCP

People and agents use Teak without the web app through the public REST API, the `teak` CLI and the MCP server, all authenticated with an API key. A card created through any of them shows up in the others and in the web app.

## Sub-features

- `api-auth` rejects a missing or revoked key with 401, and `GET /v1/me` answers with a valid one.
- `api-cards` creates, gets, lists, searches, trashes, restores and permanently deletes cards (`/v1/cards`), and runs bulk operations (`/v1/cards/bulk`) that clean tags the same way a single create does. Bulk items follow the single-card rules: a blank `url`, blank `content` on a card that isn't text, a file `cardType` without an upload (even with a `url`), and any edit to a card in Trash (other than `restore` and `delete`) fail that item. A bulk `create` or `update` item with a field it doesn't take, or an `update` item with nothing to change, fails with `INVALID_INPUT`; bulk `create` trims `notes` and drops a blank one. `PATCH` `removeAiTags` matches ignoring case.
- `api-tag-ops` renames, merges and deletes tags (`/v1/tags/rename|merge|delete`, and MCP's tag tools); the tag being changed may be an older one up to 256 characters, while a new name stays at 64.
- `api-duplicate` finds a saved link under any of its addresses (`GET /v1/cards/duplicate`, `teak cards duplicate`, MCP's `teak_v1_check_duplicate_url`, and the extension's badge): `http`/`https`, a leading `www.`, the host's case, a default port, one trailing slash, a fragment and `utm_*`, `fbclid` and `gclid` don't count; other parameters and their order, the path's case, a `#/` or `#!` route and any other port (`http://…:443`) do. Archived cards match, Trash doesn't, and of two cards for one link the newest is returned. A card with no key (the pack's `/l/` cards) matches only its exact address.
- `api-resave` saves a link that's already in Teak without a second card: `POST /v1/cards` with just the link (`url`, or `content` that is only the link, any variant `api-duplicate` matches) answers 200 `status: "created"` with `resaved: true`, `wasArchived: true` for an archived card, and the existing card, whose `savedAt` is now and `createdAt` unchanged; it leaves Archive and tops `sort=newest`. Tags and notes sent with it are ignored, a link with other words makes a new card, a match only in Trash makes a new card, and it works at 200 of 200 cards on the free plan. An `Idempotency-Key` replay returns the first answer. Bulk `create` items say `resaved: true`, and the same link twice in one request makes one card. `teak add <url>` prints "Already in Teak, moved to the top: <id>", `teak cards get` prints "Saved again <date>", and MCP's `teak_v1_create_card` text reads the same. Every card in the API has `savedAt`, and so does `cards.json` in an export.
- `cli-changes` prints `teak cards changes` as card lines, then `deleted <id>` lines, with `Next page: --next …` on stderr while more pages remain.
- `api-tag-limits` trims a card's tags and keeps one of each case variant, and answers 400 `INVALID_INPUT` to more than 100 tags or a tag over 64 characters, on create, update and bulk alike.
- `api-uploads` saves an uploaded file as a card: `POST /v1/uploads`, a `PUT` of the bytes to its `uploadUrl`, then `POST /v1/cards` (or MCP's `teak_v1_create_card`, the CLI and Raycast) with its `fileKey`, `fileName`, `fileSize` and `mimeType` answers `status: "created"` with the new `cardId`, whichever client sent it.
- `api-transcripts` returns an audio card's `aiTranscript` from `GET /v1/cards/<id>`; list and search responses leave it out unless they ask for `include=processing`.
- `api-limits` takes `limit` on `GET /v1/cards` and `/v1/cards/changes` as a whole number from 1 (default 50), returns 100 for anything larger (the `maximum` the OpenAPI document declares), and answers `400 INVALID_INPUT` "Query parameter `limit` must be a whole number from 1 to 100" to `0`, an empty value, `abc` or `2.5`.
- `cli-cards` runs `auth status`, `cards create`, `cards search`, `cards list` and `cards delete` from this checkout.
- `mcp-tools` handles `initialize` (server `teak`, titled Teak, with icons, `instructions` and the `tools` and `resources` capabilities), `tools/list` (47 tools: 45 `teak_v1_*` plus `search` and `fetch`) and `tools/call` for `teak_v1_create_card`, `teak_v1_search_cards` and `teak_v1_delete_card`. A successful call's `content` is the one-line summary, then the result as JSON equal to `structuredContent` (hosts that draw the card view give the model only `content`), and card list and search tools return each card's `content` even when `include` leaves it out. A batch of only notifications gets `202` with no body, at the edge and in Convex.
- `mcp-validation` refuses a tool argument the tool doesn't take (`teak_v1_search_cards` with `query`) with `INVALID_INPUT` naming the ones it takes, says what is wrong with an argument in plain words (`` `cardId` is required ``, `` `isArchived` must be true or false ``, `` `limit` must be 100 or less ``), and refuses an id that isn't a Teak id (`..`). A tool calls its operation by id, so an id that is also a route word (`changes`) still names a card: `NOT_FOUND` when there is none. A message without an `id` gets no answer, one with an id under `notifications/` gets `-32601`, and in a batch each message is answered on its own.
- `api-errors` answers a wrong method on a `/v1/` path with JSON `405 METHOD_NOT_ALLOWED` and `Allow`, an unknown `/v1/` path with JSON `404 NOT_FOUND`, both with `Access-Control-Allow-Origin`; `PATCH /v1/cards/<id>` names the field it refused; `content` over 512 KiB or `notes` over 256 KiB answer `400 CONTENT_TOO_LARGE` on create and PATCH, and fail their item with that code in bulk; a path with an extra segment under a route (`/v1/highlights/<id>/x`) is `404`, not `405`; a card path served for other methods (`GET /v1/cards/<id>/save-pdf`, `GET …/done`) is `405` with `Allow`.
- `api-folder-rules` sets a manual folder's rules (`autoTags`, `autoFileQuery`, `autoFileEnabled`) on `POST`/`PATCH /v1/folders`, `teak folders rules` and `create --auto-tag --auto-file`, and MCP's folder tools. Saving them starts a rule run over existing cards (`ruleRunId`), followed with `GET /v1/folders/<id>/rule-runs/<runId>`, `teak folders rule-run --wait` and `teak_v1_get_folder_rule_run`, and undone with `POST …/undo`, `teak folders undo-rule-run` and `teak_v1_undo_folder_rule_run`. A new card that matches is filed once its AI tags are written; a card taken out by hand stays out through a refresh. `like:`/`mood:`, 11 tags and rules on a smart folder answer 400; an unknown run 404; a wrong method on a run 405; a 51st folder with rules 409 `RULE_LIMIT`.
- `cli-empty` says what an empty listing means: `teak cards favorites` with no favorites (and `search`, `trash`, `tags list`, `folders list`, `highlights list`) prints "No favorite cards yet." and the like on stderr, and with a filter such as `--tag <unused>` "No cards match those filters." with an empty stdout, exit 0; `--json` still prints the empty list on stdout.
- `cli-reliability` keeps `teak add --url` off stdin, saves piped text as text, sends an `Idempotency-Key` with `add` and `bulk`, refuses a `--created-after` that isn't a time with exit 2 before any request, and checks `export -o`'s file before starting an export.
- `cli-design` follows the CLI design rules: stdout holds only the answer and a piped listing is tab-separated with ISO times; an error names what was missing, quotes the request id and says what to run next (one JSON line with `--json`, including Commander's own usage errors); `--fields` trims JSON; `-n`/`--next` page and `--all` stops at 10,000 cards; `--created-after`/`--since` take dates and ages; `unfav`, `unpin` and `todo` undo `fav`, `pin` and `done`, and every top-level shortcut takes its `cards` command's options; `rm` is `delete` in every group and the old `tags rm` warns; `tags rename|merge|delete --dry-run` and `cards bulk --dry-run` change nothing; `--wait` stops at `--timeout`; a partly failed batch counts the failures and prints the retry; `CLAUDECODE`, `AI_AGENT` or `CI` never prompts; `teak completion` and `--help` (examples, exit codes) work offline.
- `cli-guidelines` keeps the CLI to the [CLI guidelines](https://vercel.com/design/cli) Teak follows: saved text and server messages can't send terminal escape sequences (stripped from human output, escaped in JSON); `folders delete` and `highlights delete` ask first and need `--yes` where no one can answer; every error carries a `reason` (`confirmation_required`, `missing_input`, `login_required`…), and several bad values are named at once in `problems` before any request; an unknown `--fields` name on a read exits 2 listing the fields, and after a change it warns and still prints; `teak help --json`, `teak <command> --help --json` and `teak help --search <words>` answer offline; `--tag` repeats as an OR; `-o -` streams a download to stdout and `-o json` is refused; a download appears whole (no `.part` left); `--api-key -` reads the key from stdin; Ctrl+C during `--wait` exits 130 saying the work keeps going; a terminal listing has an `ID  Type  Content  Tags  Age` header; `-v` (and the old `-V`) print the version; a daily update notice shows only to a person at a terminal (`TEAK_NO_UPDATE_CHECK=1` turns it off).

## How to get to it (user POV)

- REST: `https://reminiscent-kangaroo-59.convex.site/v1/...` on the dev deployment, with `Authorization: Bearer <key>`. Production is `https://teakvault.com/api/...`. OpenAPI is at `/openapi.json`.
- CLI: `bun apps/cli/src/index.ts …` from the repository root, with `TEAK_API_KEY` and `TEAK_API_URL` set.
- MCP: `POST https://reminiscent-kangaroo-59.convex.site/mcp`, JSON-RPC, with the same bearer key.
- A key: Settings → Integrations → API keys ([settings](./settings.md)), or `scripts/api-key.ts` below.

## Driving it with curl, the CLI and scripts/api-key.ts

Preconditions:

- The dev stack is running (`scripts/api-key.ts` signs in with its seeded account).
- Mint a key, and set the environment for the rest of the run:

```bash
bun .agents/skills/verify-teak/scripts/api-key.ts mint
export TEAK_API_KEY="$(jq -r .key .agents/.state/verify/api-key.json)"
export TEAK_API_URL=https://reminiscent-kangaroo-59.convex.site SITE=https://reminiscent-kangaroo-59.convex.site
E=.agents/.state/verify/<run-id> && mkdir -p "$E"
```

Steps:

- **REST create.** `curl -sS -H "Authorization: Bearer $TEAK_API_KEY" -H "Content-Type: application/json" $SITE/v1/cards -d '{"content":"verify-<run-id> api note","cardType":"text"}' | tee $E/api-create.json` returns 200 with `{"status":"created","cardId":…}`.
- **REST search.** `curl -sS -H "Authorization: Bearer $TEAK_API_KEY" "$SITE/v1/cards?q=verify-<run-id>&mode=keyword&include=content"` lists the card with its content. Without `include=content`, items carry no content.
- **REST saved order.** `sort=newest` and `sort=oldest` follow when a card was last saved (`savedAt`), not when it was first saved. Seed `ordering-saved` (see [find](./find.md)), then `curl -sS -H "Authorization: Bearer $TEAK_API_KEY" "$SITE/v1/cards?tag=scenario-ordering-saved&include=content"`: the first item is the link `…/resaved#…`, first saved 400 days ago and saved again yesterday; with `&sort=oldest` it is last. `createdAfter=<ms a week ago>` (the parameter keeps its name) lists it and `…/two-days`. Paging with `limit=1` and `cursor` lists each card once. Save the answers to `$E/api-saved-order.txt`.
- **REST bulk.** `curl -sS -H "Authorization: Bearer $TEAK_API_KEY" -H "Content-Type: application/json" $SITE/v1/cards/bulk -d '{"operation":"create","items":[{"content":"verify-<run-id> bulk note","cardType":"text","tags":["  ux ","ux",""]}]}' | tee $E/api-bulk.json` returns `summary.succeeded` 1 and the new `results[0].cardId`. `GET $SITE/v1/cards/<id>` shows `"tags":["ux"]`, the same as `POST /v1/cards` with that body. An `"operation":"update"` item `{"cardId":…,"tags":["  design ","design",""]}` leaves `"tags":["design"]`. The CLI's `cards bulk create` (JSON items on stdin) and MCP's `teak_v1_bulk_cards` go through the same route.
- **REST tag limits.** With the headers of REST create, `POST $SITE/v1/cards` with `{"content":"verify-<run-id> tags101","cardType":"text","tags":<101 tags>}` (make them with `jq -nc '[range(101)|"t\(.)"]'`) returns 400 `{"code":"INVALID_INPUT","error":"A card can have at most 100 tags"}`, and one tag of 65 characters returns 400 `"Each tag must be at most 64 characters"`. Exactly 100 tags, one of them 64 characters long, return 200. `"tags":["  Design ","design","DESIGN","","  ","ux"]` creates the card with `"tags":["Design","ux"]`; `GET $SITE/v1/cards/<id>` reads the same. `PATCH $SITE/v1/cards/<id>` with 101 tags returns the same 400, and so does a 65-character tag ("Each tag must be at most 64 characters"); a bulk `create` item with 101 tags fails alone with `results[0].code` `INVALID_INPUT`. Save each status and body to `$E/api-tag-limits.txt`.
- **REST bulk rules.** With a marked link card `L` and a marked text card `T` moved to Trash: bulk `update` `{"cardId":L,"url":""}` fails with `INVALID_INPUT` and `GET` still shows the url; `{"cardId":L,"content":""}` fails with "Text content cannot be empty for this card type"; bulk `update` and `favorite` on `T` fail with `NOT_FOUND` and `GET /v1/cards?trashed=true` shows `T` unchanged, while bulk `restore` succeeds. Bulk `create` `{"cardType":"image","url":"https://example.com/a.png"}` fails with the same "needs an uploaded file" message as `POST /v1/cards`.
- **REST tag ops.** `POST $SITE/v1/tags/delete` with a 70-character `tag` reaches the backend (404 "Tag not found" when no card has it), and `POST /v1/tags/rename` with a 65-character `to` returns 400.
- **Duplicate check.** Seed the `url-variants` pack from `packages/convex`: `bunx convex run devSeed:seedScenario '{"workosUserId":"<id>","scenario":"url-variants"}'`, with the id from `.agents/.state/dev-account.json`. Its links live under `https://example.com/url-variants/k/…` (keyed) and `…/l/…` (no key, for the exact-address fallback).   - a `cardId` for `http://example.com/url-variants/k/www`, `https://www.example.com/url-variants/k/utm?utm_campaign=z#x` and `https://example.com:443/url-variants/k/slash`;
  - `null` for `https://example.com/url-variants/k/ids?id=3`, `https://example.com/url-variants/k/app#/other`, `http://example.com:443/url-variants/k/scheme` and `https://example.com:80/url-variants/k/slash`;

- **REST errors.** `curl -sS -i -X DELETE -H "Authorization: Bearer $TEAK_API_KEY" $SITE/v1/cards` returns `405`, `Allow: GET, POST, OPTIONS` and `{"code":"METHOD_NOT_ALLOWED",…}`; `curl -sS -i $SITE/v1/nothing` returns JSON `404` with `Access-Control-Allow-Origin: *`. `PATCH $SITE/v1/cards/<id>` with `{"isArchived":"yes"}` returns 400 "`isArchived` must be true or false"; `POST $SITE/v1/cards` with `notes` of 262,145 characters returns 400 `CONTENT_TOO_LARGE`; 262,144 saves. Save each to `$E/api-errors.txt`.
- **CLI empty listing.** `bun apps/cli/src/index.ts cards favorites --tag verify-<run-id>-none` exits 0 with an empty stdout (`2>/dev/null | wc -c` is 0) and "No cards match those filters." on stderr; `--json` prints `"items": []`. Save the output to `$E/cli-empty.txt`.
- **CLI reliability.** `(sleep 30) | bun apps/cli/src/index.ts --json add --url https://example.com/verify-<run-id>` returns at once with the card (it doesn't wait for stdin); `… cards list --created-after soon` exits 2 with "must be a time" (and `--created-after 2026-01-01` sends `createdAfter=1767225600000`); `touch $E/x.zip && … export -o $E/x.zip` exits 2 with "--force" and `GET $SITE/v1/exports/latest` is unchanged. Save each to `$E/cli-reliability.txt`.
- **CLI design.** With `T="bun apps/cli/src/index.ts"`, the run's marker `M=verify-<run-id>`, and every command's stdout, stderr and exit code saved to `$E/cli-design.txt`:
  - Output. `$T add "$M design" --tags $M` prints the id; `$T ls --tag $M | cat -A` shows one line of tab-separated fields (`^I`) ending in an ISO time; `$T --json --fields id,tags ls --tag $M` prints items with only `id` and `tags`; `$T --fields id ls` exits 2 "--fields works with --json" before any request.
  - Errors. `$T cards get cnoexist000000000000000000` exits 4 with "Card not found: cnoexist…", a `Request ID:` line when the deployment sends one, and the `teak search` hint; `$T --json ls --zzz` exits 2 with one JSON line, `"code":"USAGE"`.
  - Paging and times. `$T ls -n 1 --tag $M` (after a second card) prints one line and `Next page: --next <c>`; `$T ls -n 1 --tag $M --next <c>` prints the other. `$T ls --created-after 1d --tag $M` lists them; `--created-after 2099-01-01` lists none.
  - Undo commands. `$T fav <id>`, `$T unfav <id>`, `$T pin <id>`, `$T unpin <id>`; `$T fav <id> --remove` still unfavorites and warns "--remove is now its own command". `$T --json cards get <id>` ends with `isFavorited` false and `isPinned` false.
  - Dry runs. `$T tags rename $M $M-x --dry-run` prints "Would rename … on 2 cards in your library, and on any in Archive and Trash. Nothing changed." and `$T --json tags` still lists `$M`; `echo '[{"cardId":"<id>","isFavorited":true}]' | $T cards bulk favorite --dry-run` prints "Would run favorite on 1 item; each has the fields it needs.", and without `isFavorited` it exits 2 naming the missing field.
  - Agents and batches. `CLAUDECODE=1 $T tags delete $M` exits 2 "add --yes to confirm"; `$T restore <id> cnoexist000000000000000000` prints the restored id, then "1 of 2 cards done; 1 failed." and "Retry the failed ones: teak restore cnoexist…" (rm, restore, archive and unarchive send one `POST /v1/cards/bulk` per 100 ids; a malformed id fails as `INVALID_INPUT`, exit 1, a missing one as `NOT_FOUND`, exit 4).
  - Offline. `$T --help` lists "Exit codes:" with 130; `$T cards list --help` ends with examples; `$T __complete cards unf` prints `unfavorite`; `$T completion zsh | head -1` is `#compdef teak`.
- **CLI guidelines.** With `T` and `M` as above, after `$T add "$M guide" --tags $M` (id `<id>`), save every command's stdout, stderr and exit code to `$E/cli-guidelines.txt`:
  - Escapes. `$T cards update <id> --notes "$(printf 'x \033]0;owned\007 y')"`; `$T cards get <id> | grep -c $'\033'` prints 0 and the line reads `notes: x ]0;owned y`; `$T --json cards get <id> | grep -c '\\u001b'` prints 1.
  - Consent. `CLAUDECODE=1 $T --json folders delete $M-none` and `CLAUDECODE=1 $T highlights delete h_none` each exit 2 with `"reason":"confirmation_required"` (or "add --yes to confirm") and make no request.
  - Reasons and problems. `$T --json cards get` exits 2 with `"reason":"missing_input"`; `$T --json ls --limit zero --type spaceship` exits 2 with a `problems` array of two entries; `$T --json --api-key bad whoami` has `"reason":"login_required"`.
  - Fields. `$T --json --fields id,idd cards get <id>` exits 2 "unknown field \"idd\"; fields here: …" with an empty stdout; `$T --json --fields id,nope fav <id>` exits 0 printing `{"id": "<id>"}` and a `"reason":"unknown_fields"` warning line on stderr.
  - Help. `TEAK_API_KEY= $T help --json | jq -r '.commands[].command' | head -3` lists commands with no key; `$T cards list --help --json | jq .examples`; `$T help --search trash forever | head -1` starts with `teak cards delete (teak rm)`.
  - Filters and files. `$T add "$M other" --tags $M-b` then `$T ls --tag $M --tag $M-b` lists both cards. For a file card `<file-id>`, `$T download <file-id> -o - | wc -c` is the file's size, `$T download <file-id> -o json` exits 2, and `ls -a` shows no `.part` file after `$T download <file-id> -o $E/f --force`.
  - Key and version. `printf '%s' "$TEAK_API_KEY" | TEAK_API_KEY= $T --api-key - whoami` prints the account; `$T -v` and `$T -V` print the same version.
  - Ctrl+C. `$T export --wait & sleep 2; kill -INT $!; wait $!; echo $?` prints "Stopped." and "The export keeps going on Teak. Check on it with: teak export status", then 130 (skip when an export ran this week: it exits with the rate limit first).
  - Terminal-only output. In a real terminal (`script -qc "$T ls --tag $M" /dev/null`) the listing starts with `ID  Type  Content  Tags  Age`; piped it has no header.
- **Unauthenticated.** `POST $SITE/mcp` and `GET $SITE/v1/me` without a key both return 401.
- **Key state.** `bun .agents/skills/verify-teak/scripts/api-key.ts check` prints the status `GET /v1/me` answers with the saved key: 200 while it works, 401 once revoked.
- **Cross-surface proof.** A card created through the API appears in the web app when you search its marker ([find](./find.md)).
- **Cleanup.** Permanently delete every card the run created, then `bun .agents/skills/verify-teak/scripts/api-key.ts revoke` (it also clears a key someone already revoked in Settings).

## Gotchas

- Without `TEAK_API_URL`, the CLI silently targets production (`https://teakvault.com/api`). Set it to the dev `.convex.site` origin, with no `/v1` or `/api` suffix.
- The dev deployment has no `/api` prefix; that path exists only behind the production edge proxy.
- `?permanent=true` on a card that isn't in Trash returns 409 `NOT_IN_TRASH`. Trash it first.
- Search defaults to hybrid (meaning plus words) and lists related seeded cards too. Pass `mode=keyword` (REST, MCP) or `--mode keyword` (CLI) for exact checks.
- A hex color or quoted text is reclassified after creation; poll for the type to change. `"cardType":"text"` pins it.
- `--permanent` without `--yes` fails with exit 2 outside a terminal, and in an agent's shell (`CLAUDECODE` is set in Claude Code) even in a terminal. CLI exit codes: 0 ok, 1 API error or a `--wait` timeout, 2 usage, 3 auth, 4 not found, 5 rate limited, 130 Ctrl+C.
- The live backend may be another branch's push. The doctor says which; backend changes need `bun run dev --detach --push`.
- A free account holds a limited number of cards. Past it (for example after seeding `shuffle-partial`), every create answers 400 `CARD_LIMIT_REACHED` before tags are checked, so run the create steps on an account with room.
- MCP tools refuse arguments they don't declare: `teak_v1_search_cards` takes `q`, and `{"query":…}` answers `INVALID_INPUT` naming the arguments it takes.
- MCP is stateless JSON-RPC: no session id, and plain JSON responses. It needs `Content-Type: application/json` (415 otherwise) and an `Accept` that includes JSON (406 otherwise).
- Never paste the key into notes, PRs or chat. Write `<redacted>`.
