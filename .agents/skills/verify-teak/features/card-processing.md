# Card processing

After a save, Teak settles the card's type in the background, adds AI tags and a summary, and for links, files and media fetches previews, thumbnails, palettes and transcripts; each stage ends completed or failed in the card's processing status. A card edited mid-run is processed again; the older run never overwrites the newer.

## Sub-features

- `processing-stages` takes a new card's `processingStatus` stages (classify, categorize, metadata, renderables) from pending to completed, with AI tags and summary.
- `ai-language` writes the AI tags and summary in the content's main language (English when it has none, or for an image with no text) and stores it as `cards.aiLanguage` (`ja`, `es`…), readable only from the run's output or the card document.
- `ai-unreachable-link` gives a link whose page couldn't be read (preview failed or came back empty) no AI summary or tags, unless a site summary, article or transcript gave text: the metadata stage completes with nothing, not a description invented from the URL. A link not yet previewed is still described from its URL.
- `processing-run` is the Workflow run: one instance per card revision, `card-<cardId>-<rev>`, with steps, attempts, output and errors.
- `link-fetch-gave-up` keeps a link's run going after "fetch link metadata" uses its 5 tries (renderer down, a 5xx, a 429 or a timeout): "save failed link preview" stores a failed preview, as a 404 does, "categorize" and "generate metadata" still run, and the run ends `complete`. A refresh keeps its stored preview instead ("keep link preview after refresh").
- `processing-files` covers the Files bucket objects a run stores (thumbnails, previews, screenshots) under the account's key prefix. A preview image refused with 429 or a 5xx is retried in the last step, "store link preview image", for about 7½ minutes, and lands as `linkPreview.imageStorageKey`; a 404 or a non-image is not retried.
- `link-low-detail-screenshot` keeps a near-blank page's screenshot off its link tile, using the stored JPEG's size, `linkPreview.screenshotBytes`: under 32 KB for 1280×720 (`isLowDetailScreenshot`, `shared/screenshotDetail.ts`) the tile uses the text layout (title and description), or the page's own image if any. A screenshot without a size is kept.
- `processing-logs` covers a run's Core Worker logs and traces: warnings, errors and each invocation's outcome.
- `processing-crons` runs the Core Worker's scheduled jobs (maintenance, AI usage rollup, export cleanup) on demand.

## How to get to it (user POV)

- Save a card anywhere (composer, API, CLI, MCP, extension); its tags and summary appear on the card and in its dialog within seconds.
- Users don't see the run. On the local E2E stack the Core Worker serves Cloudflare's Local Explorer UI at `http://127.0.0.1:<coreWorker>/cdn-cgi/local/explorer` (`ports.coreWorker` in `bun run dev --status --json`) and its REST API at `/cdn-cgi/local/explorer/api` (the OpenAPI document is the API root).

## Driving it with the API and Local Explorer

Preconditions:

- The local E2E stack, which runs the Core Worker under `wrangler dev --local`: `bun run dev --stop`, then `bun run --cwd packages/tests e2e:stack` in the background (prints "E2E stack is up"). Ports are in `.agents/.state/stack.json` (`ports.coreWorker`, `urls.apiOrigin`); a worktree has its own. These steps can't reach the dev deployment's Worker, which runs on Cloudflare.
- An emulator account with an API key: call `createApiAccount("verify")` from `packages/tests/src/helpers/app.ts` in a short `bun --no-env-file` script; keep the key in `.agents/.state/verify/<run-id>/`.

Steps (with `X=http://127.0.0.1:<coreWorker>/cdn-cgi/local/explorer/api` and `API=<apiOrigin>`, from `ports.coreWorker` and `stack.urls.apiOrigin` in `bun run dev --status --json`):

- **Save.** `curl -X POST $API/v1/cards -H "Authorization: Bearer $KEY" -H 'content-type: application/json' -d '{"content":"verify-<run-id> sourdough starter notes"}'`. Response: `cardId`, with `processingStatus.classify` and `.metadata` `pending`.
- **Run.** `curl $X/workflows/teak-e2e-card-processing/instances`: an instance `card-<cardId>-1` is `running`, then `complete`. `curl $X/workflows/teak-e2e-card-processing/instances/card-<cardId>-1`: `result.steps` lists "load card", "classify", "generate metadata", "emit completion" and "report complete", each `success: true`, and `result.output` is `{"mode":"completed", …, "metadata":{"aiTagsCount":4,"hasSummary":true, …}}`. Or, in `apps/core-worker`: `bunx wrangler workflows instances describe teak-e2e-card-processing latest --local --port <coreWorker>` (tables).
- **Language.** The "generate metadata" step output and `result.output.metadata` carry `"aiLanguage":"en","aiPromptVersion":3` (the fake AI always answers English). The card document has `aiLanguage: "en"` (the local backend's Convex dashboard, or `bunx convex data cards`); the public API doesn't return it.
- **Second view.** `curl $API/v1/cards/<cardId> -H "Authorization: Bearer $KEY"`: `aiTags` and `aiSummary` filled, every `processingStatus` stage `completed`.
- **Unreachable link.** `curl -X POST $API/v1/cards … -d '{"content":"https://example.com/verify-<run-id>-missing"}'` (a 404 path). Once its run is `complete`, `GET $API/v1/cards/<cardId>`: `linkPreview` has `status: "error"`, `aiSummary` is absent, `aiTags` is empty, and `processingStatus.metadata` is `completed`. The run's output has `"metadata":{"aiTagsCount":0,"hasSummary":false, …}`. The web dialog shows no summary, and "Archived copy" says "The page couldn't be reached". Without the stack: `bun test apps/core-worker/src/workflows/cardProcessing/metadata.test.ts` ("a page that couldn't be reached gets no invented summary or tags").
- **Logs.** `curl -X POST $X/local/observability/query -H 'content-type: application/json' -d '{"sql":"SELECT level, message FROM logs WHERE level IN (?, ?) ORDER BY ts_ms DESC LIMIT 20","params":["error","warn"]}'`. Root spans: `SELECT service, name, outcome, duration_ms FROM spans WHERE parent_id IS NULL ORDER BY start_ms DESC`.
- **Files.** `curl "$X/r2/buckets/teak-files-e2e/objects"` lists stored objects, keyed `users/<user key>/cards/…` (seeded uploads included). `curl "$X/r2/buckets/teak-files-e2e/objects/<key>"` returns one.
- **Deleted files.** A signed file link stops serving once its object is deleted, even if edge-cached. Sign a URL for a key with `buildFileSigningPayload` and the stack's `E2E_FILES_SIGNING_SECRET` (`scripts/dev/local-stack/coreWorker.ts`), `GET` it twice (200, same `ETag`), then delete the card through the API, or the object with `bunx wrangler r2 object delete teak-files-e2e/<key> --local --persist-to .agents/.state/e2e-core-worker/state --config .agents/.state/e2e-core-worker/wrangler.json` in `apps/core-worker`. The link now answers 404; an object replaced under its key answers with the new `ETag` and bytes.
- **Traces on the dev deployment.** Save a card through the app or the dev API, then in the Cloudflare dashboard: Workers & Pages, `core-worker-dev`, Observability, Traces, and search for the card ID. Root span `RPC invocation` (`CardProcessingWorkflow`) has one `do` span per step in order, with the Convex, R2, `LinkFetcher`, `MediaRenderer` and `ObjectDeletionGate` calls nested inside; the instance ID is on its Logs tab. The dispatch (`POST /__ops/v1`), uploads (`PUT /__upload/v1/…`) and `/__image-source` requests are separate traces. Wrangler's OAuth login gets 403 from the telemetry API, so take step names and durations from `bunx wrangler workflows instances describe teak-card-processing-dev card-<cardId>-1 --config development/wrangler.jsonc` in `apps/core-worker`.
- **Crons.** `curl "$X/local/workers"` lists Workers with bindings and crons. `curl -X POST "$X/local/scheduled?worker=teak-files-e2e" -H 'content-type: application/json' -d '{"cron":"45 * * * *"}'` runs that job now and answers `"outcome":"ok"`. `0 3 * * *` also deletes pasted link jobs finished over a week ago, and `15 * * * *` folder rule runs past their undo window: seed an old row with `bunx convex import --table linkPasteJobs --append <file>.jsonl` in `packages/convex` (a `done` job with `finishedAt` eight days back), fire `0 3 * * *`, and `bunx convex data linkPasteJobs` is empty; `bunx convex data cronHeartbeats` lists `cleanup-finished-link-pastes` and `cleanup-expired-folder-rule-runs` as `succeeded`.
- **Regression proof.** `bun test apps/core-worker/src/workflows/cardProcessing/engine.test.ts` runs card processing on the Workflows engine against a fake Convex: retries, a stale write ending the run as skipped, errored runs reported back.

- **Low-detail screenshots.** Save `https://blank.org/?teak-verify=<run-id>` and `http://info.cern.ch/?teak-verify=<run-id>` and wait for the "screenshot" stage. Both tiles show the text layout (screenshots about 6 KB and 28 KB); the seeded links (50–360 KB) keep theirs. Read sizes from the live `searchCardsPaginated` results (`injectFaults(page, { observe })`, `metadata.linkPreview.screenshotBytes`). Then delete both for good.

## Gotchas

- `ai-language` needs real Workers AI: prove it on the dev deployment once its Core Worker runs this code. `bun --no-env-file run scripts/seed/ai-language-check.ts --seed --wait 15` seeds the `ai-languages` pack on this checkout's dev account and prints each card's expected language, `aiLanguage`, summary script and per-language accuracy (ja, es, de, ko, zh and fr must reach 90%). Images, PDFs and audio aren't seeded: upload a photo of Japanese signage, a photo with no text, a German PDF and a Spanish voice note in the app and read their dialogs.

- Links saved before this fix keep their URL-written summaries; "Refresh details" on one, with the page still unreachable, empties its AI tags but keeps the old summary. Prove the fix on a new or imported link.
- A text or quote card with no text skips the AI: metadata completes with no tags or summary. Prove it with `bun test apps/core-worker/src/workflows/cardProcessing/metadata.test.ts`, or on the E2E stack: save a note, empty its `content` through the API, read it once the run is `complete`.
- The E2E stack's AI is a deterministic fake (`apps/core-worker/e2e/fakeAi.ts`): tags are the content's first words; the summary starts "Saved note about". It doesn't answer the card-type decision, so a text card logs `malformed_clef_response` (op `decide-card-type`), expectedly, and keeps the rules' type.
- Workers AI at capacity: every op answers `AI_CAPACITY` (429) and the step retries, with nothing reported to PostHog. Images and decisions retry twice in the op first; text metadata and embeddings leave it to the step. The fake AI never runs out: prove it with `bun test apps/core-worker/src/opContract.test.ts`, or on the dev deployment via the Worker's logs for `AI_CAPACITY` during a burst of image uploads.
- A link whose text is another form of its URL (`www.`, trailing slash, fragment, `utm_` parameters) stays a link, even a `.pdf`: classification uses the save's own test (`shared/utils/bareLink.ts`). Save `https://www.example.com/report.pdf?utm_source=x` through the API and read the card's `type`.
- Browser Run, Vectorize and the two Containers aren't on the E2E stack, so link fetching, screenshots, media rendering and embeddings fail there as if those services were down; prove those on the dev deployment.
- "Refresh details" fetches a link's page again instead of reusing the day-long copy in `LINK_PAGE_CACHE`. Prove it on the dev deployment with a changed page, or with `bun test apps/core-worker/src/workflows/cardProcessing/linkMetadata.test.ts`.
- An edit bumps the revision: the next run is `card-<cardId>-2`, and the older one is stopped (`terminated`), or, if it reaches Convex first, ends `complete` with output `{"mode":"skipped","reason":"superseded"}`. An `errored` instance is a real failure; see `result.error` and the logs.
- Explorer state in `.agents/.state/e2e-core-worker/state` is wiped when the E2E stack restarts. Clean up by stopping the stack (Ctrl-C on `e2e:stack`, or ending its background command); the emulator account goes with it.
- Never call `DELETE` or `PATCH …/status` on a run you use as evidence.
