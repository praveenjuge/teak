# Browser extension

The Chrome and Firefox extension saves the current page when its popup opens, from the context menu, and with a shortcut that skips the popup. Its toolbar icon reports shortcut saves and marks pages already in Teak; re-saving moves a card to the top.

## Sub-features

- `ext-sign-in` signs in from the popup through the hosted AuthKit window. Requests go through `teak-sdk` (`createTeakClient` with `createOAuthSession`): the access token refreshes a minute before expiry, and a 401 refreshes it and resends; only a refused refresh signs the extension out.
- `ext-shortcut` saves the active tab: "…", then "✓" ("Saved to Teak" or "Already in Teak"); "!" with the reason where it can't save (`chrome://`, add-on stores, `file:`); the popup when signed out or at the card limit, or, if the popup can't open, "!" with "You've reached the free limit" / "Upgrade to Pro for unlimited cards." in the account's language. Two quick presses make one card.
- `ext-resave` re-saves a page (popup, context menu, inline buttons, shortcut) with one `POST /v1/cards`, no duplicate check: `resaved: true` shows "Already in your Teak" in the popup ("Already in Teak" on the icon), and the card moves to the top and out of Archive.
- `ext-api-url` sends every API request to `VITE_PUBLIC_API_URL` when the build sets it (production uses `https://teakvault.com/api`, the edge proxy), else to `VITE_PUBLIC_CONVEX_SITE_URL`. A sign-in saved by an older build for the Convex site URL keeps working and is re-saved for the API URL; a development build keeps storage keyed by the Convex site URL, so changing its API URL doesn't sign it out.
- `ext-errors` words known save failures in the popup's language: no connection or a timeout reads "Couldn't reach Teak. Check your connection and try again.", and a refused burst (`RATE_LIMITED`) "Too many saves at once. Wait a moment and try again.", under a translated title ("Couldn't save this page", "Couldn't save" or "Couldn't upload file"); others keep the API's message. The tag and note fields word the same two failures (on `PATCH /v1/cards/<id>`) above **Retry** and keep what was typed; other failures there read "Couldn't save tags." or "Couldn't save the note."
- `ext-badge` shows "✓" / "Already in Teak" on a saved page's tab, checked on tab activation, page load and window focus, cached five minutes per address. The check drops the `#fragment` (`#/` and `#!` routes stay), so anchor moves send nothing. Incognito and browser pages are never checked; sign-out clears every badge.
- `ext-context-menu` saves from the right-click menu (**Save Page to Teak**, **Save Text to Teak**, **Save Asset to Teak**) and opens the popup to follow it. Without `chrome.action.openPopup` (Chrome before 127, some Chromium browsers), it saves without the popup.
- `ext-font` sets the popup in Allo, the web app's font, also in Chrome, whose extension-page `body` font would otherwise beat Tailwind's `font-sans`.

## How to get to it (user POV)

- Toolbar icon → popup → **Sign in**.
- Any page → Alt+Shift+S (⌥⇧S on Mac); change it at `chrome://extensions/shortcuts` (**Save this page to Teak**) or Firefox's **Manage Extension Shortcuts**; its name is translated (`packages/i18n`, `extension.manifest.saveCommand`).
- Hover the Teak icon for its tooltip.

## Driving it with Playwright, Xvfb and xdotool

Preconditions:

- The dev stack is running and the doctor passes. `bun run setup --target extension` wrote `apps/extension/.env.local`, and `(cd apps/extension && bunx wxt build --mode development)` built `.output/chrome-mv3-dev`. Never use a production build (it signs in against production).
- `Xvfb :99 -screen 0 1440x900x24 &` and `xdotool` (`apt-get install -y xdotool`); run every script with `DISPLAY=:99`.
- An API key from `scripts/api-key.ts mint` to read saves back.

Steps (a Node script importing `node_modules/playwright-core`, written outside the repo):

- **Launch.** Make a fresh profile directory and write `Default/Preferences` as `{"extensions":{"pinned_extensions":["negnmfifahnnagnbnfppmlgfajngdpob"]}}` to pin the icon. Then `chromium.launchPersistentContext(profile, { headless: false, viewport: null, args: ["--disable-extensions-except=<build>", "--load-extension=<build>", "--window-size=1440,900"] })`, taking the service worker from `context.serviceWorkers()` or the `serviceworker` event.
- **`ext-sign-in`.** Open `chrome-extension://<id>/popup.html`, click button "Sign in", take the AuthKit window from the context's `page` event. Fill textbox "Email" with the stack account, click "Continue with email", fill textbox "Password", click "Sign in". The window closes; the popup shows the saved page (icon, title, site), and button "Menu" (⋯) opens the account's email and menu items "Open Teak", "Upload file" and "Sign out".
- **Read the icon.** In the service worker: `chrome.tabs.query({ active: true, lastFocusedWindow: true })`, then `chrome.action.getBadgeText({ tabId })` and `chrome.action.getTitle({ tabId })`. For a picture, crop the top 90 px of `import -window root shot.png`; `ffmpeg -f x11grab -framerate 15 -video_size 1440x900 -i :99 out.mp4` records the window.
- **`ext-shortcut`.** Open `https://example.com/?verify-<run-id>=1` (the run marker) and press the shortcut with a real key event: `xdotool search --onlyvisible --class chromium | tail -1 | xargs -I{} xdotool windowfocus {}; xdotool key alt+shift+s`. Within 300 ms the icon reads "…" / "Saving to Teak…", then "✓" / "Saved to Teak". `GET /v1/cards/duplicate?url=<page>` returns a `cardId`. On `chrome://version` the icon reads "!" with "Cannot save content from chrome: pages…", clearing 5 seconds later. Press twice on a new page: `GET /v1/cards?q=verify-<run-id>` lists one card for it. At the limit (seed `card-limit-199`, save one page), press on another page: the popup opens with "You've reached the free limit". With `chrome.action.openPopup = () => Promise.reject(new Error("no gesture"))` in the service worker, press again: `getTitle` reads the same two lines, and in German (Settings → Appearance → Deutsch, then reopen the popup so `/v1/me` stores it) "Sie haben das kostenlose Limit erreicht".
- **`ext-resave`.** Seed `resave` ([api-cli-mcp](./api-cli-mcp.md), **Re-save**) on the signed-in account and log context requests with `/v1/cards`. Open `https://example.com/resave/030` (archived) and the popup: one `POST /v1/cards`, no `GET /v1/cards/duplicate`, and "Already in your Teak". `GET /v1/cards?limit=1` lists that card first with `isArchived: false`, and `GET /v1/cards?q=resave/030` lists one card. The shortcut on the same page: "✓" / "Already in Teak", still one card.
- **`ext-sign-in` refresh.** In the service worker set the `accessToken` in `chrome.storage.local.get("teakOAuthCredentials")` to `"x".repeat(32)` and open the popup: still signed in, a new access token is stored, and the context logged one `401` from `/v1/me`, a token refresh and a `200`. A dead `refreshToken` too signs it out ("Sign in").
- **`ext-api-url`.** Sign in with a development build without `VITE_PUBLIC_API_URL`, then rebuild with it set to another URL reaching the same deployment (with the edge proxy, its `/api`), keeping the profile (reload the extension from `chrome://extensions`; see Gotchas). With service worker network events on, open the popup: still signed in, every Teak request goes to the new base URL, and after the next token refresh `chrome.storage.local` holds the credential with `siteUrl` set to it. The edge path is proven only after a release (the popup's requests go to `teakvault.com/api`); `apps/extension/__tests__/lib/oauthAuth.test.ts` covers the rest.
- **`ext-badge`.** Set `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` and log context requests with `/v1/cards/duplicate`. A page saved earlier: "✓" / "Already in Teak" after one request. An unsaved page: no badge, "Save to Teak". Switch between them with `bringToFront()`: the badge follows, with no new requests. On the saved page, go to `#access_token=x`, then `#a`, then `#/inbox`: the badge stays "✓", only `#/inbox` sends a request (its `url` keeps `#/inbox`), and none carries `access_token`.
- **`ext-errors`.** The local stack has no WorkOS Connect clients, so seed the sign-in: make an account and key with `createApiAccount` (`packages/tests/src/helpers/app.ts`), read its `id` from `GET /v1/me`, and in the service worker write `teakOAuthCredentials:<convex site URL>` = `{ accessToken: <key>, refreshToken: "unused", expiresAt: Date.now() + 36e5, siteUrl: <convex site URL>, issuer: <the emulator origin>, clientId: "client_local", userId: <id> }` and `teakOAuthOwner:<convex site URL>` = `<id>` (the Convex site URL and emulator origin come from `bun run dev --status` and `.agents/.state/stack.json`; build with `VITE_PUBLIC_CONVEX_URL` and `VITE_PUBLIC_CONVEX_SITE_URL` set to the local stack's). With `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, route `/v1/me` to answer `locale: "de"`, and `POST /v1/cards` to `route.abort("internetdisconnected")` or a 429 `{ "code": "RATE_LIMITED" }`. Open `popup.html` in a tab, an init script making `chrome.tabs.query({ active: true })` answer an `https://example.com/?verify-<run-id>=1` tab. The popup reads "Diese Seite konnte nicht gespeichert werden" and "Teak ist nicht erreichbar. Prüfen Sie Ihre Verbindung und versuchen Sie es erneut." (or "Zu viele Speicherungen auf einmal. …"); with `locale: "en"`, the English lines above. For the tag and note fields, route `PATCH /v1/cards/<id>` instead, fill the combobox with a tag and press Enter: the bar above "Erneut versuchen" reads the same German line, and the tag stays.
- **`ext-context-menu`.** Seed the sign-in as in `ext-errors`, route `https://example.com/**` to a small HTML page, and open `https://example.com/?verify-<run-id>=1`. With xdotool, `windowfocus` the Chromium window (Xvfb has no window manager, so not `windowactivate`), right-click the page (`mousemove 700 500 click 3`), find **Save Page to Teak** with `import -window root` and left-click it. The popup shows "Page saved", `chrome.storage.local`'s `contextMenuSave.status` is `success`, and `GET /v1/cards/duplicate?url=<page>` returns a `cardId`. Set `chrome.action.openPopup = undefined` in the service worker and repeat on a new page: no popup, no `unhandledrejection`, and the card is saved.
- **`ext-font`.** Open `chrome-extension://<id>/popup.html` signed out. `getComputedStyle(document.body).fontFamily` starts with `Allo` (not the browser's UI font, e.g. "Inter, Arial, sans-serif"), and once painted `document.fonts` lists `Allo` with weight `100 900` as loaded. The heading "Save anything, anywhere" shows Allo's single-story "a".
- **Cleanup.** Delete run-marker cards (`DELETE /v1/cards/<id>`, then `?permanent=true`), revoke the key, delete the profile, stop Xvfb.

## Gotchas

- Chrome keeps an unpacked extension's old service worker across launches of a profile, so a rebuild keeps running the old build. Use a fresh profile every run; `chrome.runtime.reload()` doesn't reload a `--load-extension` build.
- Playwright's `page.keyboard.press` goes to the page and never fires an extension shortcut; only a real X key event (`xdotool`) does.
- The release bundle is minified; grep the source, not `background.js`.
- The badge checks `http://localhost` pages too, which the API refuses (400), so the web app's tab has no badge.
- Firefox, Safari and incognito aren't reachable this way; Firefox needs its own run, and `apps/extension/__tests__/lib/savedPageCheck.test.ts` covers the incognito skip.
